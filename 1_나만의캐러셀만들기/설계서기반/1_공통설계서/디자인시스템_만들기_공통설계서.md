# 디자인 시스템 만들기 — 공통 설계서

- 판: 1판(2026-11-09), 새로 설계하는 판에 맞춰 고침(2026-11-12). 모든 약사님 묶음에 똑같이 들어간다. 그 계정 **사실**(편 표·그림 크기·쓰면 안 되는 장·물을 것)은 `3_작업안내/`에 있다. 그 계정 **설계**(대표 편·부품 목록·부품별 값·글꼴)는 정해져 있지 않다 — `시작.md` 2~6단계에서 클로드가 `1_공통설계서/설계하기.md`대로 만들고(`7_결과/설계/`·`2_커스텀설계서/`·`5_글꼴/글꼴표.json`), 이 문서는 그다음 만들기(7~13단계)를 말한다.
- 읽는 사람: 약사님 컴퓨터의 클로드. 약사님은 코딩을 모르므로, 클로드가 이 문서대로 하고 약사님께는 쉬운 말로 묻고 알린다.
- 이 문서가 쓴 경로는 모두 **묶음 폴더 안 상대 경로**다(예: `6_도구/합치기.py`). 도구는 묶음 폴더에서 `python3 -I 6_도구/<도구>.py …`로 돌린다.

## 0. 무엇을 만드나 — 낱말 풀이

**디자인 시스템 화면**은 그 계정 카드뉴스를 다시 만들 때 쓰는 "부품 견본 모음"이다. Claude 아티팩트 종류 "Design System" 한 개로 만든다. 그 안의 **부품 견본** 하나하나는 그 계정 실제 게시물 한 장을 HTML로 똑같이 다시 그린 1080×1350 장이다. 목표는 **실제 게시물과 섞어 놓아도 구별이 안 되는 견본**이다. 이 화면과 노션 기획안으로 나중에 캐러셀을 만든다(이 묶음 밖).

| 낱말 | 뜻 |
|---|---|
| 부품 | 장의 모양 한 가지(예: 사진 표지, 번호 목록, 격자 표, 마지막 장). 영문 이름 하나(예: `NumberList`) |
| 근거 장(잰 장) | 그 부품을 보고 맞출 원본 한 장. 편 아이디 + 장 번호(예: `AbCd123xYz 4장`) |
| 근거_모두 | 같은 모양이 나온 다른 원본 장들(모양·순서 참고용) |
| 원본 견본 | 화면에 실제 원본 장을 몇 장 함께 보여 주는 카드(`OriginalSamples`, 선택) |
| 모양 계열 | 눈에 보이는 꼴 묶음(표지 / 카드 / 표 / 번호 목록 / 실사+글상자 / 마지막 장 …). 한 편 안에서 같은 계열은 1장만 쓴다 |
| 커스텀 json | `2_커스텀설계서/디자인시스템_커스텀.json` — 그 계정 값(공통과 다른 값만) |
| 공통 json | `2_커스텀설계서/디자인시스템_공통.json` — 모든 계정 기본값 |
| 최종 json | `2_커스텀설계서/디자인시스템_최종.json` — 둘을 도구로 합친 것. **장 안 숫자·색·글꼴은 여기 값만 쓴다** |
| 블라인드 | 만든 장과 원본 장을 섞어 다른 클로드(판정자)에게 "어느 게 만든 건지" 맞히게 하는 검사 |
| `_AI생성` | AI로 그린 그림 파일 이름에 붙이는 꼬리표 |

## 1. 폴더 지도

```
묶음 폴더/
├── 읽어주세요.md          약사님(사람)용 안내
├── CLAUDE.md              클로드가 자동으로 읽는 규칙
├── 시작.md                진행 순서표(여기서 시작)
├── 1_공통설계서/          이 문서(만들기) + 설계하기.md(설계 2~6단계)
├── 2_커스텀설계서/        커스텀 설계서(md, 빈 양식) + 커스텀 json(빈 틀)·공통 json → 5단계에서 채우고 합치기로 최종 json
├── 3_작업안내/            그 계정 사실(편 표, 그림 크기·영상 장, 쓰면 안 되는 장, 물을 것)
├── 4_규칙/                금지목록.md + 지킬규칙.md
├── 5_글꼴/                무료(OFL) 후보 글꼴 파일 + 라이선스 + 글꼴표.json(6단계에서 채움)
├── 6_도구/                도구(파이썬) + 도구_사용법.md
└── 7_결과/                클로드가 채우는 곳
    ├── 설계/              설계 2~6단계 결과: 계정메모·대표편·모양표·부품목록·글꼴비교
    ├── 게시물/            모은 원본: <날짜>_<아이디>/1.jpg, 2.jpg …
    ├── 디자인시스템화면/  project/(components·fonts·tokens.json·README.md), 사진아이디.json, 게시용/
    ├── 올릴사진/          부품에 쓰는 그림 조각(영문 파일 이름)
    ├── 블라인드/          회차마다 폴더(1회차/, 2회차/ …)
    └── 기록/              진행 기록·비교 그림·백업·끝 기록
```

`7_결과/올릴사진/`은 그림찍기 도구가 `7_결과/디자인시스템화면/올릴사진/`에서 찾는다. 그래서 **0단계에서 `7_결과/디자인시스템화면/올릴사진`을 `7_결과/올릴사진`을 가리키는 바로가기(심볼릭 링크)로 만들거나, 처음부터 그림을 `7_결과/디자인시스템화면/올릴사진/`에 둔다.** 둘 중 하나로 정해 기록에 적는다(권장: 바로가기 — `ln -s ../올릴사진 7_결과/디자인시스템화면/올릴사진`).

## 3. 0단계 — 준비

1. **폴더 확인**: 묶음 폴더 안에 위 1장의 폴더가 모두 있는지 본다. 묶음 폴더 이름·위치는 약사님 마음대로여도 된다(도구는 경로를 인자로 받는다).
2. **파이썬**: `python3 --version` → 3.9 이상이면 된다. 없으면 맥이 "명령어 도구 설치"를 물어보는 창을 띄운다 — 약사님께 "설치 누르기"를 부탁한다(무료, 몇 분).
3. **Pillow**(그림 다루는 파이썬 부품): `python3 -c "import PIL; print(PIL.__version__)"`. 없으면 `python3 -m pip install --user Pillow`. 이것 말고 다른 것은 설치하지 않는다.
4. **크롬**: `/Applications/Google Chrome.app`이 있는지 본다. 없으면 약사님께 구글 크롬 설치를 부탁한다(무료 — https://www.google.com/chrome/). 다른 위치면 환경변수 `CHROME`.
5. **글꼴**: `5_글꼴/`의 후보 파일(OFL)과 `5_글꼴/글꼴표.json`이 있는지만 본다. 쓸 글꼴은 6단계(`설계하기.md` 6장)에서 고르고, 그때 고른 글꼴 파일(.ttf·.woff2)과 라이선스(.txt·.pdf)를 `7_결과/디자인시스템화면/project/fonts/`로 **복사**한다. 후보에 없는 글꼴은 받지 않는다.
6. **도구 시험**: `python3 -I 6_도구/합치기.py 2_커스텀설계서` → "남은 선택지" 보고가 나오면 된다(파일은 안 바뀐다). 커스텀 json이 빈 틀이라 "덮은 칸 0 · 새 칸 0"이 정상이다.
7. **올릴사진 바로가기**(1장 끝 문단).
8. `7_결과/기록/진행.md`를 만들고 0단계 결과를 적는다.

**함정**
- `python3`가 아니라 `python`만 되는 컴퓨터가 있다 — 둘 다 해 본다.
- `pip install`이 "외부 관리 환경" 오류를 내면 `--user`를 붙였는지 본다. 그래도 안 되면 멈추고 약사님께 상황을 알린다(다른 설치 프로그램을 받지 않는다).
- 글꼴 파일을 고치지 않는다(이름 바꾸기·잘라 줄이기·형식 바꾸기 모두). 복사만.

## 4. 1단계 — 게시물 모으기(받은 자료 확인)

> **자료가 `0_수집분석/`에 이미 있으면 이 장은 확인만 한다.** 묶음에 `0_수집분석/게시물/<날짜>_<아이디>/1.jpg …`가 들어 있으면 아래 "내 정보 다운로드"·브라우저 저장을 하지 않는다(약사님께 부탁하지도 않는다). 대신 ① `0_수집분석/읽어주세요.md`를 읽고 ② 작업안내 1장 편 표와 폴더를 맞춰 편 수·장 수·빠진 편·영상 장(`출처.json`의 `영상 장`)을 확인해 `7_결과/기록/진행.md`에 표로 적는다. 이 문서의 다른 장이 `7_결과/게시물/…`이라고 쓴 자리는 `0_수집분석/게시물/…`을 가리키는 바로가기(0단계에서 만듦 — `시작.md`)로 읽는다. 바로가기를 못 만드는 컴퓨터면 도구에 `0_수집분석/게시물/…` 경로를 그대로 넣는다(도구는 경로를 인자로 받는다). `0_수집분석/` 안 파일은 원본이므로 고치지 않고, 잘라 쓸 때는 복사해서 쓴다. 아래 본문은 자료가 없는 묶음(직접 모으는 경우)용이다.

목표: 작업안내 "모을 게시물" 표의 편을 `7_결과/게시물/<날짜>_<아이디>/1.jpg, 2.jpg …`(장 순서대로)로 둔다. 날짜는 한국 날짜, 아이디는 인스타 주소 `instagram.com/p/<아이디>/`의 그 글자.

### 기본 방법 — 인스타그램 "내 정보 다운로드"
1. 약사님께 부탁한다(본인 계정이라 본인이 직접 해야 한다). 인스타 앱 기준:
   프로필 → 오른쪽 위 메뉴(☰) → **계정 센터** → **내 정보 및 권한** → **내 정보 다운로드(정보 다운로드)** → 다운로드 또는 전송 → 이 계정 선택 → **일부 정보** → **게시물**(콘텐츠 묶음 안) → **기기로 다운로드** → 기간 **전체 기간** → 형식 **JSON** → 미디어 화질 **높음** → 파일 만들기.
   - 메뉴 이름은 앱 판마다 조금 다를 수 있다. 비슷한 이름을 찾으면 된다.
   - 파일이 준비되기까지 **몇 분에서 며칠** 걸릴 수 있다. 준비되면 인스타 알림·이메일이 오고, 같은 메뉴에서 받는다(받을 때 비밀번호를 다시 물을 수 있다 — 약사님이 직접 입력).
2. 받은 압축 파일을 약사님이 `7_결과/게시물/받은파일/`에 넣는다(클로드는 "어디에 두셨어요?"라고 위치를 묻는다).
3. 클로드가 압축을 `7_결과/게시물/받은파일_풀림/`에 푼다. 그 안에서 `posts_1.json`(이름이 조금 다를 수 있음 — `posts`가 든 json)과 `media/posts/…` 그림 파일을 찾는다.
4. **편 맞추기**: 내려받은 파일에는 게시물 아이디가 **없을 수 있다**. 그래서 작업안내 표의 ① 게시 날짜(내려받은 파일의 시각은 세계 표준시라 한국 날짜와 하루 다를 수 있음) ② 캡션 첫 줄 ③ 장 수 세 가지로 맞춘다. 셋 중 둘 이상이 맞고 나머지가 설명되면(예: 영상 장이 빠져 장 수가 적음) 같은 편으로 본다. 애매하면 약사님께 표지 그림을 보여 주고 묻는다.
5. 장 순서대로 `1.jpg, 2.jpg …`로 복사한다(원본 파일은 그대로 둔다). 영상 장(.mp4)은 그림이 아니므로 번호만 건너뛰고 `빠진장.txt`에 "3장 = 영상"처럼 적는다.
6. 편마다 `출처.txt`에 원래 파일 이름·게시 시각·캡션 첫 줄을 적는다(캡션 전문은 적지 않아도 된다).
7. 모은 결과를 `7_결과/기록/진행.md`에 표로: 편 · 장 수 · 그림 크기(예 1080×1350) · 빠진 장.

### 대안 — 클로드 브라우저로 하나씩 저장
"내 정보 다운로드"가 오래 걸리거나 안 될 때만.
- 인스타 로그인은 **약사님이 직접** 한다. 비밀번호를 클로드에게 알려 주지 않는다(클로드도 묻지 않는다).
- 본인 공개 게시물 주소를 하나씩 열어 장 그림을 가장 큰 크기로 저장한다. 파일을 내려받기 전에 약사님께 "이 편 그림 n장을 내려받을게요" 허락을 받는다.
- **천천히**: 한 편 받고 몇 초 쉬기, 한 번에 20편 이내. 너무 빨리 많이 열면 인스타가 막는다. 막히면 멈추고 다음 날 다시.
- 유료 수집 서비스(Apify 같은 것)는 쓰지 않는다.

**함정**
- 영상 장의 미리보기 그림(작고 흐림)을 장 그림으로 쓰지 않는다 — 글꼴·색을 잴 수 없다.
- 그림이 가로 1080보다 작으면(예: 720) `출처.txt`에 "해상도 낮음"을 적는다. 그런 장은 모양 참고로만 쓰고, 색·크기를 재는 데 쓰지 않는다.
- 다른 사람 얼굴·아이 얼굴이 나온 장도 모아 두는 것은 괜찮다(근거 확인용). 견본 그림에 쓰지 않을 뿐이다.

## 5. 7단계 — 부품 견본 만들기

부품 목록은 `7_결과/설계/부품목록.md`(설계 4단계에서 클로드가 정한 것)에 있다. 부품마다 아래를 한다. 한 번에 한 부품씩, 끝내고 다음으로.

### 5-1. 부품 하나 만드는 순서
1. **값 읽기**: 최종 json에서 그 부품의 견본 칸(부품목록의 `json 칸`, 예: `부품.근거·목록.견본_번호_목록`)을 읽는다. 안에 `고정`·`바꿔_끼우는_자리`·`요소`(잰 위치·크기·색·글꼴크기)·`다음_위`·`추가_요소`가 있다(꼴은 커스텀 json 빈 틀의 `_견본_칸_꼴`). **이 값이 견본의 뼈대다.** css로 옮기는 법은 `설계하기.md` 5-6.
2. **근거 장 보기**: `7_결과/게시물/`의 그 장과 비교용 사본(`7_결과/기록/근거1080/` — 설계하기 5-3)을 Read로 연다. 1080이 아니면 1080 기준으로 환산한다(1440 원본은 ×0.75, 1320은 ×1080/1320). 가로 1080 미만 장은 값을 재는 데 쓰지 않는다.
3. **그림 조각 준비**: 사진·제품·아이콘·꾸밈 그림은 그 계정 게시물에서 잘라 `7_결과/올릴사진/`에 영문 이름(예: `part-numlist-arrow.png`)으로 둔다. 순서와 규칙은 5-3.
4. **preview.html 쓰기**: `7_결과/디자인시스템화면/project/components/<영문이름>/preview.html` — 꼴은 5-5.
5. **값검사**: `python3 -I 6_도구/값검사.py 7_결과/디자인시스템화면/project/components 2_커스텀설계서/디자인시스템_최종.json` → 그 부품 "없는 값 0건".
6. **README.md 쓰기**(5-6).
7. `7_결과/기록/재료.json`에 그 부품 줄(이름·근거 장·쓴 그림 파일과 출처)을 더한다.

### 5-2. 값 규칙 (꼭)
- 장 안(`.slide` 안쪽)의 **모든 숫자(px)·색(hex)·글꼴 이름은 최종 json에 있는 값만** 쓴다. 되풀이되는 칸(둘째 카드·셋째 줄)은 json 값끼리 `calc()`로 잇는다(예: `top:calc(379px + 300px + 12px)`) — 새 숫자를 만들지 않는다.
- json에 없는 값이 꼭 필요하면 **원본 픽셀을 재서** 넣는다:
  1. 고치기 전 커스텀 json을 `7_결과/기록/백업/디자인시스템_커스텀_<날짜시각>.json`으로 복사(덮어쓰지 않는다).
  2. 그 부품 견본 칸의 `추가_요소`에 값을, `추가_근거`에 "편 아이디 n장, 어떻게 쟀는지"를 넣는다. 지어낸 값 금지.
  3. `2_커스텀설계서/커스텀_설계서.md`의 "부품 견본 값" 절에 같은 내용을 한 줄로 적는다.
  4. `python3 -I 6_도구/합치기.py 2_커스텀설계서 --write`로 최종 json을 다시 만든다(최종 json은 손으로 고치지 않는다).
  5. 값검사 다시 → 0건.
- 장 안 값은 꼭 **`style="…"` 속성**에 적는다. `<style>` 블록에 적은 값은 값검사가 못 본다(그 블록은 장 밖 카드 틀용).
- **글자 크기** = 원본 글자 위에 겹쳐 보며 맞춘 글꼴 크기(json `글꼴크기`). 잰 "글자 높이"를 글꼴 크기로 쓰면 한글은 약 10%, 숫자는 약 25% 작게 그려진다.
- 한 장 전체를 줄이고 키우는 것은 `.scale`의 `transform:scale()` 하나로만 한다. 글자·여백을 따로 줄이지 않는다.
- 3:4·1:1 원본을 4:5 장으로 옮기는 법은 부품마다 정해 두었다(부품목록 "원본 처리" — 설계하기 5-3). 적힌 대로만 한다.

### 5-3. 그림 규칙
- **사람 얼굴은 약사님 본인만.** 아이·배우자·다른 사람 얼굴은 견본 그림에 쓰지 않는다. AI로 얼굴을 만들거나 고치지 않는다.
- **제품 사진**: ① 그 계정 게시물 실사에서 잘라 쓰기 → ② 브랜드·제조사 공식 사이트 실사(출처 기록) → ③ 둘 다 없을 때만 AI 일반 영양제 그림(상표·글자 없음, 파일 이름 `_AI생성`, 돈이 들어 **약사님 확인 뒤**). 성분표·검사지·근거 자료는 실사·원본만.
- **아이콘·꾸밈 그림**: ① 그 계정 원본 게시물에서 잘라 쓴다(손그림 화살표·별·체크 상자·붓자국·알약 그림 등) → ② 없으면 AI 그림(`_AI생성`, 약사님 확인 뒤). **이모지를 아이콘 대신 쓰지 않는다.** 글머리 기호(☑ ❌ ❗ ✓ 같은 글자)는 근거 장에 글자로 쓰인 것만 글자로.
- 원본 그림이 캔바 요소처럼 **약사님이 출처를 아는 그림**이면, 약사님께 출처와 써도 되는지 묻고 써도 되면 잘라 쓴다. 출처를 모르면 쓰지 않는다.
- 약사님이 **원본 캔바 디자인·원본 사진 파일**을 갖고 있으면 그게 더 깨끗하다 — 써도 되는지 묻고 쓴다.
- 사진 위에 얹힌 원본 글을 지울 때는 **글자 자리만** 둘레 색으로 메운다. 얼굴·제품은 손대지 않는다. 지운 파일 이름에 `_보정`을 붙이지 않아도 되지만 README "깔개·그림 처리"에 무엇을 지웠는지 적는다.
- 가운 가슴 이름 자수(실명)·이름표·소매 약국 로고처럼 실명·상호가 보이는 곳은 지운다.
- AI 그림을 만들 때는 한 번에 여러 개를 한 장에 그려 잘라 쓰면 비용이 준다. AI 표시(C2PA 같은)는 지우지 않는다.

### 5-4. 함정 (네 계정에서 실제로 겪은 것)
- **칸 이름·글은 원본 전체 그대로.** 줄이거나 바꾸면 바로 들킨다(예: "PMS (생리전 증후군)"을 "PMS"로 줄였다가 들킴). 두 줄이 되면 두 줄로.
- **같은 카드 반복·자로 잰 간격은 들킨다.** 원본이 크기가 다른 카드를 섞었으면 똑같이 섞는다. 줄 간격·그림 크기는 원본에서 잰 값 그대로(원본 줄 간격 54인데 67로 벌렸다가 들킴).
- **광택 3D AI 아이콘은 들킨다.** 원본이 무광 사진풍이면 원본에서 잘라 쓴 조각이 훨씬 낫다.
- **진짜 글꼴이 없으면 가장 잘 들킨다.** 원본 글꼴을 모르면 무료(OFL) 후보를 같은 크기로 그려 원본 글자와 겹쳐 보고(폭·높이·잉크 양) 가장 가까운 것을 고른다. 고른 근거를 커스텀 json·md에 적는다.
- **글꼴 라이선스**: OFL(오픈 폰트 라이선스)만 자유롭게 넣고 고칠 수 있다. 그 밖의 글꼴은 그 회사 조건을 확인한다. 조건을 지키며 쓸 때도 **파일을 고치지 않는다**(잘라 줄이기·형식 바꾸기 금지). 웹(아티팩트)에 싣는 것이 조건부인 글꼴은 확인 전에는 싣지 않는다.
- **크롬이 못 읽는 글꼴 파일이 있다**(글자 간격표 문제). 크롬에서 안 불리면 기록하고, 사본을 만들어도 되는지 그 글꼴 조건을 보고 약사님께 묻는다.
- 원본에 있는 **작은 꾸밈**(반짝 선, 손그림 동그라미, 'OK' 도장, 노랑 칩, 글자 테두리)이 빠지면 휑해 보여 들킨다. 원본을 확대해 꾸밈 목록을 먼저 만든다.
- 그림을 덮어 지운 자리에 **길이가 다른 글**을 얹으면 옛 자국이 보일 수 있다 — 짧은 글·긴 글로 바꿔 넣어 시험한다.
- 720 원본에서 잘라 쓴 사진은 흐리다 — 크게 키우지 않는다.

## 8. 10단계 — 블라인드 검수

목적: 만든 장이 실제 게시물 사이에서 티가 나는지, **아무것도 모르는 다른 클로드**에게 맞혀 보게 한다.

### 8-1. 묶음 만들기
- **만든 장 4장**: 8단계 그림 중 4개. 처음에는 서로 다른 모양 계열로 고른다. 회차마다 바꿔 가며 모든 부품이 한 번 이상 들어가게 한다.
- **원본 장 4장**: `설계하기.md` 7-1대로 고른다(쓰면 안 되는 장은 작업안내 2장). 규칙:
  - 세로 **4:5** 장만(3:4는 도구가 위아래를 조금 잘라 4:5로 맞춘다). **정사각(1:1) 원본은 늘리면 일그러져 불공평하므로 쓰지 않는다.**
  - **근거 장·근거_모두 장·원본 견본 장이 나온 편은 통째로 쓰지 않는다**(판정자가 같은 편끼리 비교하게 됨). 그래서 모자라면 설계하기 7-1 "모자랄 때"대로 하고 기록에 적는다.
  - **회차마다 처음 쓰는 원본**으로 고른다. 영상 장은 안 쓴다.
- 도구:
```
python3 -I 6_도구/블라인드묶음.py --만든 7_결과/기록/그림/A.png 7_결과/기록/그림/B.png 7_결과/기록/그림/C.png 7_결과/기록/그림/D.png \
  --원본 7_결과/게시물/<편1>/2.jpg 7_결과/게시물/<편2>/5.jpg 7_결과/게시물/<편3>/4.jpg 7_결과/게시물/<편4>/3.jpg \
  --출력 7_결과/블라인드/1회차
```
  - 만드는 것: `g/tile_1~8.jpg`(선명, 540×675), `g/blur.jpg`(흐림 4×2 모아보기 — 칸 360×450: 1080×1350을 180×225로 LANCZOS로 줄였다가 BILINEAR로 360×450으로 키우고 GaussianBlur 1.5), `key.json`(정답 — 판정 끝까지 열지 않음), `질문.txt`.

### 8-2. 판정자 2명
- **서로 다른 새 서브에이전트 2명**(Agent 도구, 새 일반 에이전트). **포크(fork)는 쓰지 않는다** — 포크는 지금 대화를 다 알고 있어 정답을 안다.
- 판정자에게는 **자기 그림 경로와 질문 문장만** 준다. 부품 이름·계정 이름·몇 장이 만든 것인지·key.json 위치를 알려 주지 않는다. "다른 파일은 열지 마라"를 넣는다.
  - **판정자 A(흐림)**: `g/blur.jpg` 한 장.
  - **판정자 B(선명)**: `g/tile_1.jpg ~ tile_8.jpg` 여덟 장.
- 질문 문장(전문 — `질문.txt`에 그림 경로까지 채워져 있다):

> 인스타그램 약사 계정(한국어 건강·영양제·공구 게시물) 캐러셀 장 8장{A: 을 4×2로 모은 흐린 그림이다(칸 위 숫자가 번호) / B: 이다(폰 크기 낱장 8장, 파일 이름의 숫자가 번호)}. 일부는 그 계정이 실제로 올린 장이고, 일부는 다른 사람이 그 계정 스타일을 흉내 내 만든 장이다. 몇 장이 만든 것인지는 알려 주지 않는다. 그림: {경로}. 이 그림만 Read로 보고 다른 파일은 열지 마라. 각 칸마다: 실제/만든 것, 확신(낮음/중간/높음), 이유 한 줄. 표로.

### 8-3. 판정과 기록
- 두 판정이 다 온 뒤 `key.json`을 열어 맞춰 본다.
- **통과 기준: 만든 4장 중 3장 이상을 '실제'로 봄** — 판정자마다 따로 센다. 둘 다 통과면 통과. 하나만 통과면 이유를 보고 11단계에서 판단한다(흐린 그림 판정자는 그 계정 카드형 장의 공통 모양 때문에 원본까지 '만든 것'으로 고르는 일이 많았다).
- `7_결과/기록/블라인드_<회차>.md`에 표로 적는다: 번호 · 정답 · A 판정(확신) · B 판정(확신) · 판정 이유.

## 9. 11단계 — 들킨 곳 고치기

1. 골라진 만든 장마다 판정 이유를 적고, **근거 장과 겹쳐 본다**(9단계 도구).
2. **그 이유가 원본에도 있는 모양이면 고치지 않는다.** 판정자는 다른 편 원본과 비교해 말하는 일이 많다. 예: "같은 카드 반복·큰 빈 곳·대문자 계정명" → 원본도 같았음(안 고침). "제목 줄바꿈이 어색" → 근거 장 원본 그대로였음(안 고침).
3. **원본과 다른 것만 원본대로 고친다.** 예: 카드 크기를 원본처럼 섞기, 줄 간격을 원본 값으로, 줄인 칸 이름을 원본 전체로, AI 아이콘을 원본 조각으로, 빠진 꾸밈 넣기.
4. 고친 값은 5-2 규칙대로(커스텀 json → md → 합치기 → 값검사 0). 고친 부품은 다시 찍는다.
5. **다시 볼 때는 처음 쓰는 원본 + 새 판정자 2명**으로 8장을 다시 한다. 고친 부품 + 아직 안 본 부품을 섞는다.
6. 3번 고쳐도 통과하지 못하면 멈추고, 남은 이유와 판단을 기록해 약사님께 알린다(앤서니에게 보낼 내용).

## 10. 12단계 — 아티팩트(Design System)로 올리기

**먼저 약사님께 묻는다**: "디자인 시스템 화면을 Claude 아티팩트로 올려도 될까요? 처음에는 약사님만 볼 수 있는 비공개 페이지예요." 허락이 있을 때만 한다.

1. 아티팩트 종류 목록에서 **"Design System"**을 찾는다(Artifact 도구 — quickstart 또는 `list` scope `types`). 그 종류의 `type_url`로 새 아티팩트를 만든다(제목 예: "<표시이름> 디자인 시스템"). 돌아온 **종류 안내(instructions)를 먼저 읽고, 이 문서와 다르면 그 안내가 우선**이다.
2. **화면 파일 준비**(`7_결과/디자인시스템화면/project/`):
   - `tokens.json` — `python3 -I 6_도구/토큰만들기.py 2_커스텀설계서/디자인시스템_최종.json 7_결과/디자인시스템화면/project --이름 <폴더 표시이름>` (글꼴 파일이 `project/fonts/`에 먼저 있어야 함)
   - `README.md` — 소개서: 표시이름·@핸들(실명·연락처 넣지 않음), 한눈에 보는 스타일, 색·글씨, 종류별 장 구성, 부품 목록, 쓰지 않는 것, 아직 고르지 않은 것·확인 전 목록. 값은 최종 json에서. 프로필 사진을 넣으려면 data URI로(아이·가족 얼굴은 잘라 냄).
   - `components/<부품>/preview.html`·`README.md`, `fonts/`
3. **그림 올리기**: `7_결과/올릴사진/`의 그림을 그 아티팩트의 자산(asset)으로 올린다(한 번에 25개까지). 올린 결과의 주소를 `7_결과/디자인시스템화면/사진아이디.json`에 `{"파일이름": "주소"}`로 적는다.
4. **게시용 만들기**: `python3 -I 6_도구/게시준비.py 7_결과/디자인시스템화면 <네임스페이스> <부품1> <부품2> …` (부품 순서 = 화면 카드 순서, `7_결과/설계/부품목록.md`). 아이디 빈 그림이 있으면 멈춘다 → 3으로.
5. **게시**: 종류 안내대로 `게시용/project/components/…`, `bundle.js`, `tokens.json`, `README.md`, `fonts/` 파일을 그 아티팩트 주소에 올린다. 같은 주소로 다시 올리면 고친 판이 된다(주소를 바꾸지 않는다).
6. 약사님께 주소를 알려 드리고 함께 본다. 카드 아래 "글꼴 못 부름"이 0건인지, 그림이 모두 보이는지 눈으로 확인한다.

**함정**
- 그림 파일을 고치면 다시 올려야 한다. `사진아이디.json`의 그 칸을 빈칸으로 만들고 3부터.
- 글꼴 파일도 화면 파일과 함께 올려야 화면에서 불린다.
- 아티팩트 화면 안은 다른 출처라 밖에서 글꼴 검사를 못 한다 — 카드 스크립트와 눈으로.
- README 안 그림은 data URI만 보인다.
- 아티팩트를 공개하거나 다른 사람과 공유하는 것은 약사님이 정한다. 클로드가 마음대로 공유하지 않는다.

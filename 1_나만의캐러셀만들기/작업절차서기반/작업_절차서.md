# 작업 절차서 — 약사님 한 분: 수집·분석 → 설계서 → 디자인 시스템 → 캐러셀

약사님 인스타 계정 하나를 받아, 그 계정을 수집·분석해 **설계서**를 만들고, 설계서로 **디자인 시스템**을 만든 뒤, 기획서를 받으면 그 디자인 시스템으로 **캐러셀**을 만든다. 이 문서 하나만 보고 처음부터 끝까지 진행할 수 있게 적었다. 필요한 파일은 진행하면서 이 작업 폴더 안에 새로 만들고, 다른 폴더의 자료는 읽거나 고치지 않는다.

**목표**: 기획서 하나를 주면, 그 약사님이 원래 올리던 것과 구별이 안 되는 캐러셀(카드뉴스)이 나온다.

**실패 조건**(하나라도 걸리면 그 편은 다시 만든다)
- 그 약사님 스타일이 아니다(색·글씨·말투가 그 계정 것이 아님).
- 가운데 정렬·똑같은 상자·그라데이션·장식 아이콘 범벅 같은 "AI 카드뉴스" 모양이다.
- 기획서에 없는 사실·수치가 들어갔다.
- 광고 기준을 넘는 말(효능 단정·약사 추천형·효능 체험담)이 들어갔다.
- AI로 만든 인물이 들어갔다.

## 입력과 결과

| 입력 | 언제 |
|---|---|
| 약사명(표시이름)과 인스타 아이디 → 약사님 폴더 이름 `{표시이름}_{인스타계정}` (예: `홍길동약사_hong_yaksa`) | 처음 한 번. 아래 모든 명령의 `$A` |
| 기획서(노션 대본 링크, 붙여넣은 글, 마크다운 파일 중 무엇이든) | 4단계에서 편마다 |

| 단계 | 끝나면 생기는 것 | 끝난 조건 |
|---|---|---|
| 1. 수집 | `$A/01_…`·`$A/02_…` (게시물목록·분류.md·대표 편 슬라이드) | `수집검증.py` "통과" |
| 2. 분석 → 설계서 | `$A/03_분석/{날짜}_모양표.md`, `$A/04_설계서/설계서.md`·`디자인시스템.json`(부품 목록 포함), `공통/금지목록.md` | 2-7 완료 기준 전부 |
| 3. 디자인 시스템 | 부품마다 견본(`$A/05_디자인시스템/부품/<부품>/`) + Design System 아티팩트 1개(부품 = 컴포넌트) | 3-8 완료 기준 전부 + 담당자 확인 기록 |
| 4. 캐러셀 | `$A/06_캐러셀/{날짜}_{편이름}/` + 아티팩트 1편 | 4-8 검수 통과 + 사람 확인 |

## 실행 규칙 — 약사명과 인스타 아이디만 받고 시작할 때

"이 약사님 계정으로 절차대로 해 줘"만 받아도 아래대로 진행한다. 따로 지시가 없는 것은 이 절의 기본값을 따른다.

**약사명과 인스타 아이디는 먼저 저장소 맨 위의 `내정보.md`(작업 폴더의 두 단계 위 폴더, `../../내정보.md`)에서 읽는다.** 채워져 있으면 묻지 않고 그 값으로 시작한다(대화에서 다른 값을 받았으면 받은 값이 먼저이고, 어느 쪽을 쓸지 한 번 확인한다). 파일이 없거나 칸이 비어 있으면 약사명(인스타에 보이는 이름)·인스타 아이디·본인 계정으로 직접 하는지를 묻고, 답을 `내정보.md`에 적어 둔다. `내정보.md`에는 이 세 가지만 적는다 — 비밀번호·키·실명·연락처는 적지 않는다. "본인 계정으로 직접 진행: 예"면 "본인 계정으로 직접 할 때" 절을 따른다. 값을 얻은 뒤에는 아래 순서대로 묻지 않고 이어서 진행한다.

1. **먼저 읽는다**: 이 문서 전체 → `도구/README.md` → `공통/교훈.md` → `공통/금지목록.md`(있으면). 3·4단계에 들어갈 때 교훈을 한 번 더 본다.
2. **쓰는 것은 이 문서·`공통/`·`도구/`와 그 약사님 폴더(`$A`)뿐이다.** 작업 폴더에 다른 약사님 폴더가 있어도 열지 않고, 본뜨거나 가져다 쓰지 않는다. 교훈·금지목록에 나오는 다른 계정 이름과 게시물 아이디는 근거 표시일 뿐이다. 작업 폴더 밖은 건드리지 않는다.
3. **어디서 시작하나**: `$A/읽어주세요.md`가 없거나 비어 있으면 0부터. 있으면 그 표에서 끝나지 않은 첫 단계부터 이어서 한다(끝난 단계는 다시 하지 않는다 — 30일이 지났으면 "언제나 지키는 것"대로 묻는다).
4. **어디까지 하나**: 기획서를 받지 않았으면 3단계까지 하고 멈춘다. 기획서를 받았고 3단계가 끝나 있으면 4단계를 한다.
5. **멈추고 담당자에게 묻는 곳**(여기 말고는 묻지 않고 진행한다 — 판단 규칙은 부록 A):
   - 시작할 때 한 번: `$A/동의기록.md`가 비어 있으면 동의 범위(사진·개인 게시물 재료 사용 / 스토리 / 얼굴 외 AI 수정 / 사진을 GPT(외부 AI)로 보내기, 각각 예·아니오)와 담당자 이름을 묻는다. 답이 없거나 "아직"이면 **동의 없음**으로 적고 0-3대로 공개 슬라이드·캡션만 받아 진행한다.
   - 시작할 때 한 번: GPT 키가 있는지 본다(0-3 `키확인`). 없으면 **묻지 않고 바로** `키넣기`를 돌린다 — 맥은 숨김 입력 창이 떠서 담당자가 직접 넣고 키체인에 저장된다(창이 떴다고 한 줄 알린다). 창에서 취소하거나 5분 안에 넣지 않으면 **GPT 없음**으로 `읽어주세요.md`에 적고 진행한다(다시 띄우지 않는다 — 나중에 넣으려면 담당자가 `키넣기`를 말한다). 윈도우는 창을 띄울 수 없으니 "터미널에서 `python3 도구/부품/gpt그림.py 키넣기`를 돌려 주세요(넣지 않으면 GPT 없이 진행)"라고 한 번 알린다. **키 값은 대화창으로 받지 않는다**(붙여 주더라도 쓰지 않고 `키넣기`로 다시 넣게 한다). 화면·기록에 찍지 않는다.
   - 로그인 화면·접속 제한(1단계 멈춤 규칙) — 로그인은 사람이 한다.
   - 파일 내려받기(글꼴 등)와 설치.
   - 약사님 얼굴이 든 그림을 아티팩트에 올리기 전(3단계 5, 4단계 7).
   - 4단계: 기획서가 이 계정 것이 아닐 때 · 장별 글이 없는 기획서일 때 · 사진 재료가 모자랄 때 · 장별 글 표(디자인 전) · 캡션이 광고 기준에 걸릴 때 · 검수 3번에 통과하지 못했을 때.
   - 이 문서와 부록 A에 답이 없는 갈림길, 또는 문서·도구가 실제와 맞지 않을 때(고치기 전에 무엇이 어긋나는지 먼저 알린다).
6. **3단계 담당자 확인은 기다리지 않는다.** 3단계의 일(부품 견본·검수·화면·구성 샘플·완료 기준 검수)을 모두 끝낸 뒤 화면 주소와 함께 보고하고, **"기획서를 주시면 이 디자인 시스템으로 캐러셀을 만듭니다"라고 알리며 [부록 E](#부록-e-기획서-주는-법)의 안내를 그대로 보여 준다.** `읽어주세요.md`에는 "담당자 확인 대기"로 적는다. 확인을 대신 적지 않는다 — 담당자가 확인했다고 말하면 그때 설계서 "검토 기록" 칸에 적고 "완료"로 바꾼다. 4단계는 그 확인이 기록된 뒤에 시작한다.
7. **단계가 끝날 때마다** `$A/읽어주세요.md`를 고치고 짧게 알린 뒤 다음 단계로 간다(끝난 것 · 확인 전인 것 · 다음에 할 것). 2단계가 끝나면 글자 없는 본인 사진 수도 함께 알린다(`python3 -I 도구/사진재료.py "$A"` — 4단계에서 사진 장을 몇 장 쓸 수 있는지 미리 알기 위해).
   ```
   # {표시이름}_{계정} — 진행 상태

   | 단계 | 상태 | 날짜 | 메모 |
   |---|---|---|---|
   | 0 준비 | 완료 / 진행 중 / 대기 | 2026-00-00 | 동의 상태 |
   | 01 수집 | … | | 받은 것·수 |
   | 02 대표슬라이드 | … | | |
   | 03 분석 | … | | |
   | 04 설계서 | … | | 확인 전 칸 수 |
   | 05 디자인시스템 | … | | 부품 수 · 화면 주소 · 담당자 확인 여부 |
   | 06 캐러셀 | … | | 편 폴더 · 아티팩트 주소 · 검수 결과 |

   ## 확인이 필요한 것
   - (담당자·약사님께 물어야 할 것)
   ```
8. **검수는 만든 대화가 아닌 다른 서브에이전트에게** 맡긴다(2-7, 3-4, 3-8, 4-8). 결과는 통과·실패를 그대로 적는다.
9. 새로 들킨 것·고친 것 중 다른 계정에도 해당할 것은 `공통/교훈.md` "제안" 절에 한 줄로 적는다. 그 계정에만 해당하는 것은 `$A/04_설계서/배운점.md`에 적는다.

## 본인 계정으로 직접 할 때
이 문서는 "담당자"(작업을 시키고 확인하는 사람)와 "약사님"(계정 주인)을 나눠 적었다. 약사님이 본인 계정으로 직접 돌리면 **둘 다 본인**이다. 아래만 바꿔 읽고 나머지 규칙은 그대로 따른다.

- **"담당자에게 묻는다"·"약사님께 보인다"·"전달은 담당자"** = 대화창에서 본인에게 한 번 묻거나 보인다. 두 번 묻지 않는다.
- **동의**: 본인 계정이라 받아 올 동의는 없다. 시작할 때 범위(사진·개인 게시물 재료 사용 / 스토리 / 얼굴 외 AI 수정 / 사진을 GPT로 보내기)를 본인이 예·아니오로 답하면 `동의기록.md`에 "본인"으로 적는다. 사진에 **다른 사람**(가족·직원·손님)이 나오면 그 사진은 그 사람의 동의 없이는 재료로 쓰지 않는다.
- **3단계 담당자 확인**: 본인이 디자인 시스템 화면을 보고 "확인했어"라고 하면 설계서 "검토 기록"에 본인 확인으로 적는다.
- **4단계 9 사람 확인**: 본인이 아티팩트와 캡션을 한 번 본다.
- **기획서**: 본인이 쓴 글이면 된다(노션 링크·붙여 넣은 글·파일). 장마다 `피드1.` `피드2.`… 로 글을 나누고 캡션 완성본을 같이 주면 묻는 것이 줄어든다. 장별 글이 없으면 4단계 1의 "장별 글이 없는 기획서"대로 초안을 뽑아 본인에게 보인다.
- **그대로인 것**: 얼굴은 AI로 만들거나 고치지 않는다 · 광고 기준(금지목록) · 기획서에 없는 사실·수치를 넣지 않는다 · 로그인은 본인이 Aside에서 직접 한다 · 키는 대화창에 붙이지 않는다. 본인 것이라도 이 규칙들은 줄이지 않는다.
- 화면과 설계서에는 본인 것이라도 실명·가족 이름·연락처를 적지 않는다(아티팩트를 공유하면 남이 본다).

## 0. 준비

### 0-1. 폴더 구조
모든 명령은 작업 폴더(이 스터디 폴더 `1_나만의캐러셀만들기/작업절차서기반`)에서 실행한다(도구는 상대 경로를 작업 폴더 기준으로 찾는다).

```
1_나만의캐러셀만들기/작업절차서기반/
├── 시작.md                       ← 시작 한 줄("시작.md대로 진행해줘")
├── 작업_절차서.md                ← 이 문서
├── 도구/                         ← 고정 스크립트(도구/README.md), 부품/(부품 견본 도구), 디자인시스템_빈틀.json, 글꼴/
├── .venv-cv/                     ← OpenCV가 든 파이썬(사진보정·누끼용)
├── .env                          ← (윈도우만) GPT 키. `키넣기`가 만든다. 공유·복사하지 않는다. 맥은 키체인에 두고 이 파일을 만들지 않는다
├── 공통/
│   ├── 금지목록.md               ← 여러 계정이 같이 쓰는 것만(2단계에서 없으면 만든다)
│   └── 교훈.md                   ← 부품 견본·제작에서 들킨 것·고친 것(3·4단계 전에 읽기)
└── {표시이름}_{계정}/             ← 약사님 한 분의 모든 것(계정 단위로 복사·삭제·공유)
    ├── 읽어주세요.md              ← 진행 상태
    ├── 동의기록.md
    ├── 01_수집/                  ← 1단계: 프로필.md·프로필/, 게시물목록.md·json, 캡션수신/, 본인사진/, 개인게시물/, 사진_태그.json
    ├── 02_대표슬라이드/           ← 1단계: 분류.md, 슬라이드/{게시일}_{아이디}/(n.jpg·출처.json·글.md·사진메모.json), 한눈에보기/
    ├── 03_분석/                  ← 2단계: 도구 출력, 모양표, 분석 메모(실측·횟수·근거·사진 목록)
    ├── 04_설계서/                ← 2단계: 설계서.md, 디자인시스템.json, 검수 기록, 배운점.md
    ├── 05_디자인시스템/           ← 3단계: 부품/<부품>/(견본.json·preview.html·README.md·render.png·cmp.jpg·깔개), 블라인드/, 재료.json, 올릴사진/, 사진아이디.json, project/, 검토·검수 기록
    └── 06_캐러셀/                ← 4단계: {날짜}_{편이름}/
```

### 0-2. 약사님 폴더 만들기

```bash
A=홍길동약사_hong_yaksa   # 받은 약사명_인스타아이디로 바꾼다
mkdir -p "$A"/{01_수집,02_대표슬라이드,03_분석,04_설계서,05_디자인시스템,06_캐러셀} "$A"/01_수집/{프로필,본인사진,개인게시물,캡션수신} 공통
touch "$A/읽어주세요.md" "$A/동의기록.md"
```

`$A/04_설계서/설계서.md`가 이미 있으면 그 약사님은 2단계를 "갱신"으로 진행한다.

### 0-3. 시작 전 확인
- **사람이 준비할 것**: 맥 컴퓨터(크롬 경로·얼굴 검사가 맥 기준 — 윈도우에서는 돌려 보지 않았다) · Claude 데스크톱 앱 · Aside 브라우저(인스타는 본인이 직접 로그인해 둔다) · OpenAI 키(선택). 아래를 확인해 빠진 것은 시작할 때 **한 번에 모아** 알린다.
- 파이썬 3.9 이상 + Pillow + numpy: `python3 -c "import PIL, numpy"`가 아무 말 없이 끝나면 된다(numpy는 글꼴겹침·얼굴 검사용).
- 3단계 부품 견본용: 크롬(`/Applications/Google Chrome.app`, 다른 위치면 환경변수 `CHROME`) · OpenCV(`.venv-cv/bin/python -c "import cv2"`; 없으면 `python3 -m venv .venv-cv && .venv-cv/bin/pip install opencv-python-headless numpy pillow`).
- 4단계 얼굴 겹침 검사용: `swift --version`(맥 기본 개발 도구). 없으면 장만들기가 "얼굴 검사 못 함"을 알리고 사람이 render.png로 본다.
- **동의 기록**(`$A/동의기록.md`): 비어 있으면 공개 카드뉴스 슬라이드와 캡션만 받는다. 본인 사진·개인 게시물·스토리는 목록(아이디·날짜·한 줄 설명)만 적고 파일은 받지 않는다. 동의 없는 게시물은 디자인 참고용으로만 쓰고 재료로 쓰지 않는다.
- **GPT 키**(이미지 생성·사진 고치기용, [0-4](#0-4-gpt로-그림-만들기고치기)): 있는지 본다 — 값은 찍지 않는다.
  ```bash
  python3 도구/부품/gpt그림.py 키확인     # 끝 코드 0 = 있음(어디 있는지 알림) · 2 = 없음
  python3 도구/부품/gpt그림.py 키넣기     # 없을 때. 입력받아 저장한다
  ```
  - **저장 위치**: 맥 = 키체인(서비스 이름 `OPENAI_API_KEY`), 윈도우 = 작업 폴더 `.env`. 읽는 순서는 환경변수 `OPENAI_API_KEY` → 맥 키체인 → `.env`.
  - **넣는 법**: 맥은 키가 없으면 세션이 묻지 않고 `키넣기`를 돌려 숨김 입력 창이 뜨고 담당자가 거기에 넣는다(세션은 값을 보지 못한다). 윈도우는 담당자가 터미널에서 직접 `키넣기`를 돌려 넣는다. 바꿀 때도 `키넣기`를 다시 돌린다.
  - 모델을 바꾸려면 환경변수나 `.env`에 `OPENAI_IMAGE_MODEL=…`(없으면 `gpt-image-1`).
  - 없으면 GPT를 쓰는 자리마다 "키 없을 때" 길(OpenCV 보정·그래픽 부품)로 간다.
- **브라우저 = Aside**: 인스타·노션은 모두 **Aside 브라우저**(사용자의 실제 로그인 브라우저)로 읽는다. Claude는 Aside MCP 도구로 다룬다.
  - `browser_profiles`로 연결된 프로필(`connected: true`)을 확인하고, 회사 인스타 계정이 로그인된 프로필을 쓴다.
  - `repl`(Playwright 자바스크립트)로 페이지를 열고 읽는다: `openTab(url)` · `page.goto(url)` · `page.evaluate(fn)` · `snapshot(page)`. 한 번 호출에 120초 제한이 있으니 반복 작업은 20개 안팎씩 나눠 부른다. 변수 이름은 호출마다 새로 짓는다.
  - Aside는 **자기 세션 폴더(`pwd`)에만** 파일을 쓸 수 있다. 받은 자료는 `path.join(pwd, …)`에 쓰고, 경로를 `console.log`로 찍은 뒤 셸에서 `cp`로 작업 폴더에 옮긴다.
  - 로그인 확인: `openTab('https://www.instagram.com/')` 뒤 `snapshot`으로 로그인 상태를 본다. 로그인은 사람이 Aside 브라우저에서 직접 한다(Claude는 아이디·비밀번호를 넣지 않는다). 스토리는 열지 않는다(상대에게 조회 기록이 남는다).

### 0-4. GPT로 그림 만들기·고치기
3단계(깔개·조각 그림)와 4단계(사진 준비·배경·소품)에서 그림을 새로 만들거나 사진을 고칠 때는 GPT 이미지(OpenAI 이미지 API)를 쓴다. 키가 없으면 각 단계의 "키 없을 때" 길로 간다.

- **해도 되는 것**: ① 사진 위에 얹힌 글·스티커 지우기 ② 배경 넓히기·바꾸기 ③ 인물 없는 배경·소품·아이콘·일반 영양제 그림 새로 만들기 ④ 약사님 사진의 옷·배경 바꾸기(4단계 5의 조건에서만).
- **하지 않는 것**: 약사님 얼굴·머리 모양·손·체형·포즈를 만들거나 고치기(인물이 든 그림을 새로 만들지 않는다 — 새 포즈가 필요하면 사진을 받는다) · 제품 상표·성분표·검사지·논문·후기 캡처 만들기 · 글자가 든 그림 만들기(글은 언제나 장만들기가 얹는다).
- **생성 사진의 한계**: GPT로 새로 만든 사물·배경 사진은 실사 폰 사진을 올리는 계정에서는 블라인드에서 번번이 들켰다(매끈한 질감·상표 없는 민무늬 물건 — `공통/교훈.md`). 그래서 **사진 바탕 장을 생성 사진으로 통째로 채우지 않는다.** 새로 만들기는 그래픽 장의 소품·아이콘·일반 영양제 그림에, 고치기는 실제 사진의 작은 자리(글 지우기·옷·배경 일부)에 쓴다. 사진 장 재료는 언제나 약사님 실제 사진이 먼저다.
- **사진 보내기**: 약사님 사진을 GPT로 보내는 것은 동의기록에 "사진을 GPT로 보내기 = 예"일 때만. 아니면 사진은 OpenCV 도구로만 고치고, GPT는 사진 없이 새 그림을 만들 때만 쓴다. 실명·연락처·남의 아이디가 보이는 그림은 가린 뒤에 보낸다.
- **고칠 때는 고칠 자리만 받는다**: GPT 편집은 마스크 밖도 조금씩 다시 그린다. 그래서 도구가 결과를 그대로 쓰지 않고 **`--자리`만 원본 위에 붙인다**(나머지 픽셀은 원본 그대로 — 얼굴·손·제품이 바뀌지 않았음이 보장된다). 마스크는 얼굴·손·제품과 겹치지 않게 잡고, 글이 얼굴·머리카락 위에 있는 사진은 GPT로도 고치지 않는다.
- **크기**: `1024x1536`(세로)·`1536x1024`(가로)·`1024x1024`로 받아 장 크기(디자인시스템.json `출력_크기_기본`, 기본 1080×1350)에 맞춰 자르고 늘린다.
- **부르는 법** — `도구/부품/gpt그림.py`(키는 도구가 환경변수·키체인·`.env`에서 읽고 어디에도 찍지 않는다. 즉석 curl·코드로 따로 부르지 않는다):
  ```bash
  # 새로 만들기(인물·글자·상표 없는 그림)
  python3 도구/부품/gpt그림.py 만들기 <출력_AI생성.png> --프롬프트 "<그릴 것. 인물·글자·상표 없음>" [--크기 1024x1536|1536x1024|1024x1024] --기록 <log.md>
  # 고치기: --자리(원본 픽셀, 여러 번)만 GPT 결과로 바꾸고 나머지는 원본 그대로. 얼굴·손·제품은 --보호
  python3 도구/부품/gpt그림.py 고치기 <원본> <출력_AI생성.jpg> --자리 x0,y0,x1,y1 --프롬프트 "<그 자리에 둘 것. 예: 글자를 지우고 주변 벽 그대로>" [--보호 x0,y0,x1,y1] --기록 <log.md>
  ```
  출력 이름에 `_AI생성`이 없으면 돌지 않는다. 원본은 덮어쓰지 않는다. 끝 코드 2 = 키·입력 문제, 1 = GPT 오류(키 틀림·한도·거절) — 오류 줄을 알리고 "키 없을 때" 길로 간다. 도구는 다시 시도하지 않는다 — 같은 요청을 3번 넘게 되풀이하지 않는다.
- **기록**: 부를 때마다 `--기록`으로 `log.md`(3단계는 `05_디자인시스템/log.md`, 4단계는 편 폴더)에 한 줄씩 남긴다(날짜·모델·원본·자리·프롬프트·결과 파일). GPT가 손댄 파일은 이름에 `_AI생성`, 설계서·아티팩트 메모에 "GPT로 고친 장"을 적는다.
- **확인**: 결과는 100%로 열어 본다 — 이음선·뭉개진 결·없던 물건·글자 모양 자국이 있으면 프롬프트를 고쳐 2번까지 다시, 그래도 남으면 "키 없을 때" 길.

## 1단계 수집

인스타 API·스크레이퍼는 쓰지 않고 Aside 브라우저로만 읽는다(0-3). 게시물마다 2~4초, 150개면 10분 안팎.
**멈춤 규칙**: "Please wait / 잠시 후 다시 시도 / 429 / Something went wrong"이 나오거나 로그인 화면으로 튕기면 그 자리에서 멈추고, 어디까지 했는지 `$A/읽어주세요.md`에 적은 뒤 다음 날 이어서 한다. 같은 회사 계정으로 여러 세션이 동시에 읽지 않는다.

1. **프로필 저장** — Aside로 `https://www.instagram.com/{계정}/`을 열어 `page.screenshot()`으로 화면 한 장을 세션 폴더에 저장하고 `01_…/프로필.md`에 소개글·외부 링크·하이라이트 이름·고정 게시물 아이디·팔로워 수·게시물 수·부계정을 적는다. 프로필 사진은 그림 주소를 `fetch`로 받아 세션 폴더에 쓴 뒤 `01_…/프로필/프로필사진.jpg`로 옮긴다.
2. **게시물 목록** — Aside 프로필 탭에서 격자를 끝까지 스크롤(최근 150개, `page.mouse.wheel` + `sleep`)한 뒤 주소와 캡션(`img alt`)을 모은다. 로그인 세션이면 alt가 캡션 전문이다. 격자는 스크롤하면 앞 칸이 사라질 수 있으니 스크롤할 때마다 모아 `id`로 합친다.
   ```js
   const 칸들 = await page.evaluate(() => [...document.querySelectorAll('a[href*="/p/"], a[href*="/reel/"]')]
     .map(a => ({주소: a.href, 캡션앞: a.querySelector('img')?.alt || ''})));
   await fs.writeFile(path.join(pwd, `${계정}_격자.json`), JSON.stringify(칸들, null, 1));
   ```
   `01_…/게시물목록.json`(리스트, 항목 `순서·id·주소·게시일·유형·분류·캡션·캡션상태·받은곳`)과 `게시물목록.md`(표)로 저장한다. `캡션상태`에는 "전문" 또는 "앞부분만"만 쓰고(도구가 이 낱말로 판정), 언제 어디서 받았는지는 `받은곳`에 적는다.
3. **캡션 전문·좋아요 받기** — Aside `repl`에서 게시물마다 `https://www.instagram.com/p/{id}/`(릴스도 `/p/` — `/reel/`은 캡션이 접혀 안 읽힌다)를 `page.goto`로 열고 2초 뒤 읽어, 세션 폴더 `수신/{id}.json`에 바로 쓴다. **캡션을 눈으로 읽어 옮겨 적지 않는다.**
   ```js
   await fs.mkdir(path.join(pwd, '수신'), { recursive: true });
   for (const id of 이번_묶음) {            // 20개 안팎씩(120초 제한)
     await page.goto(`https://www.instagram.com/p/${id}/`); await sleep(2000);
     const 값 = await page.evaluate(() => ({
       og: document.querySelector('meta[property="og:description"]')?.content || '',
       caption: [...document.querySelectorAll('h1, span[dir="auto"], div[dir="auto"]')].map(e => e.innerText).sort((a, b) => b.length - a.length)[0] || '',
       time: document.querySelector('time')?.getAttribute('datetime') || '' }));
     // og = "195 likes, 8 comments - 계정 - October 15, 2026: \"캡션…\"" → likes·comments·date_og를 나눠 담는다
     const m = 값.og.match(/^([\d.,KM]+) likes?, ([\d.,KM]+) comments? - .*? - (.*?):/) || [];
     const 기록 = { id, url: `https://www.instagram.com/p/${id}/`, caption: 값.caption, likes: m[1] || '', comments: m[2] || '',
                    date_og: m[3] || '', time: 값.time, 수신시각: new Date().toISOString() };
     await fs.writeFile(path.join(pwd, '수신', `${id}.json`), JSON.stringify(기록, null, 1));
     console.log('OK', id, 값.caption.length);
   }
   ```
   묶음마다 멈춤 규칙 문구(1단계 머리)가 화면에 나왔는지 `snapshot`으로 확인하고, 나오면 그 자리에서 멈춘다. 아무것도 클릭·좋아요·팔로우하지 않는다. 다 받으면 세션 폴더의 `수신/`을 작업 폴더로 옮겨 검증 → 합치기:
   ```bash
   cp -R "<Aside 세션 폴더>/수신/." "$A/01_수집/캡션수신/"   # 세션 폴더 = repl에서 console.log(pwd)
   python3 -I 도구/캡션합치기.py "$A/01_수집" "$A/01_수집/캡션수신"
   python3 -I 도구/캡션합치기.py "$A/01_수집" "$A/01_수집/캡션수신" --write
   ```
   "앞부분 불일치"는 가장 긴 글이 댓글로 잡힌 것이다. 그 게시물만 다시 열어 `og:description` 캡션 앞 30자가 들어 있는 가장 긴 글을 `caption`으로 다시 쓰고 다시 검증한다. 1,070자 근처에서 잘린 캡션(끝에 `�`)은 인스타 한계라 `캡션상태`를 "인스타 제공 한계까지(약 1,070자에서 잘림)"로, 삭제·비공개 게시물은 "삭제·비공개된 게시물(앞부분만 남음)"로 둔다. 릴스 캡션처럼 잘림이 남는 항목은 `캡션상태`에 "잘림"을 넣어 둔다(수집검증이 건수에서 뺀다).
4. **분류** — `02_…/분류.md`에 게시물마다 종류를 [부록 A-1 판정표](#a-1-종류-판정표)로 적는다. 그 계정에서 판정표가 어긋나는 단서(예: 거의 모든 캡션에 상담 DM 문구)는 분류.md 맨 위 "판정 보충 단서"에 적는다.
5. **대표 편 고르기** — [부록 A-2](#a-2-대표-편-고르기) 규칙으로 고르고, 분류.md 맨 위 "대표 편(선정 기준·날짜)" 표에 적는다. 이후 바꾸지 않는다.
6. **대표 편 슬라이드 원본 받기** — Aside로 대표 편마다 `https://www.instagram.com/p/{id}/`를 연다. `main img` 중 `clientWidth ≥ 400`인 것이 현재 장이다(그림이 안 뜨면 `page.screenshot()`을 한 번 찍어 그리게 한다). `img.src`(1080 이상)를 적고 `button[aria-label="다음"]`을 눌러 끝 장까지 넘긴다(릴스·1장짜리는 "다음"이 없다). 적은 주소를 `fetch`로 받아 세션 폴더 `슬라이드/{게시일}_{id}/1.jpg, 2.jpg…`에 쓰고(`Buffer.from(await (await fetch(주소)).arrayBuffer())`), 셸에서 `02_…/슬라이드/`로 옮긴다. 편 폴더에 `출처.json`(아이디·주소·게시일·장수·원본해상도·받은날)을 만든다. 표지 가로가 1080 미만이면 `"해상도": "낮음"`(글꼴 분석에서 뺀다). 화면 캡처는 분석에만 쓰고 재료로 쓰지 않는다.
7. **한눈에보기**
   ```bash
   python3 -I 도구/한눈에보기.py "$A"
   ```
8. **글자 없는 사진 나누기** — 글자가 얹힌 슬라이드(디자인 분석용)와 글자 없는 사진(재료용)을 나눈다. 글자 없는 본인·제품 사진은 `01_…/본인사진/`, 일상 게시물은 `01_…/개인게시물/`(릴스 첫 화면도 후보). 사진마다 `01_…/사진_태그.json`에 장소(약국·집·야외·스튜디오)·복장(가운·사복)·분위기·글자 유무·다른 사람 얼굴 유무·쓸 수 있는 부분을 단다. 인물은 실명 대신 역할명(본인/배우자/아이/직원/타인). 동의가 비어 있으면 목록만.
9. **슬라이드 글 받아적기 + 모양 판정** — 대표 편의 장을 한 장씩 보면서 두 파일을 같이 만든다(그림을 한 번만 본다). 장이 많으면 편을 나눠 worker 여럿에 맡긴다(이미지 한도에 걸리면 편마다 장을 번호 붙여 이어 붙인 모음 그림으로 본다).
   - `02_…/슬라이드/{편}/글.md`: 장마다 `## n장` 아래 제목 / 본문(줄바꿈 그대로) / 작은 글씨 / 계정 표시 / 강조된 단어. 보이는 그대로 옮기고, 못 읽는 글자는 `[판독불가]`.
   - `02_…/슬라이드/{편}/사진메모.json`: 장마다 `{"장", "바탕"(사진 바탕 / 그래픽·단색 바탕 / 영상·자료 캡처), "글자없음", "사진": [{내용·장소·복장·분위기·다른사람얼굴·본인얼굴·쓸수있는부분{설명, 상자}}], "모양", "부품", "계열"}`.
   - **모양 판정**(`모양`·`부품`·`계열`): [부록 A-5](#a-5-모양-판정-부품-이름) 규칙. 같은 모양이면 편이 달라도 같은 부품 이름을 쓴다. 영상·자료 캡처 장은 `"부품": null`, `"모양": "캡처"`.
10. **수집 검증**
    ```bash
    python3 -I 도구/수집검증.py "$A"
    python3 -I 도구/수집검증.py "$A" --write
    ```
    ① 캡션 최장 300자 초과(아니면 잘린 것) ② 한 편 안에 같은 그림 없음 ③ 저해상도 편은 `출처.json`에 기록 ④ 모든 편에 `출처.json`. 마지막 줄이 **"통과"**여야 1단계가 끝난다. 결과는 `03_…/{오늘}_수집검증.md`에 남고, `읽어주세요.md`의 01·02 줄을 갱신한다.

## 2단계 분석 → 설계서

숫자는 도구가 세고, 사람(AI)은 판단만 한다. 즉석 코드로 따로 세지 않는다. 규칙에 없는 경우는 값을 꾸미지 말고 "확인 필요"로 두고 사람이 정한다.

1. **도구 돌리기**
   ```bash
   python3 -I 도구/슬라이드실측.py "$A" --write   # 비율·장 수·밝기·주요 색·강조색 후보
   python3 -I 도구/캡션통계.py   "$A" --write     # 끝맺음·1인칭·이모지·CTA·해시태그·광고 표시·자주 쓰는 표현·주당 편 수
   ```
   `02_…/분류.md`를 고치면 두 도구를 반드시 `--write`로 다시 돌린다(종류 비율·종류별 장 수가 분류.md를 읽는다).
2. **모양표** — 1단계 9의 장별 판정을 센다.
   ```bash
   python3 -I 도구/모양표집계.py "$A" --write   # → 03_분석/{오늘}_모양표.md
   ```
   - 맨 위 "부품 판정 전 장"이 0이어야 한다(아니면 1단계 9로 돌아가 채운다).
   - **2편 이상 반복된 모양 = 부품**(이 계정 디자인 시스템의 컴포넌트), 1편뿐 = "드묾"(부품으로 만들지 않고 가까운 부품으로 묶거나 둔다).
   - 부품마다 편·장 수, 쓰는 종류, 편 안 자리, 근거 장, 견본 장 후보가 나온다. 견본 장은 후보 중 해상도가 높고 글·사진이 대표적인 장 하나를 사람이 확정한다.
   - 정보형(건강 정보·영양제 트렌드)에서 부품이 6개 미만이거나 정보형 대표 편이 12편 미만이면, 같은 종류의 다음 좋아요 순위 캐러셀을 "참고(부품용)"로 더 받아(1단계 6·9) 다시 센다. 분류.md 대표 편 표 아래에 참고 편으로 적는다.
   - 종류별 장 순서 예와 바탕 비율도 모양표에서 읽는다(설계서 "종류별 장 구성"·"바탕 비율" 근거).
3. **분석 메모** — `03_…/{오늘}_분석메모.md`에 [부록 B 설계서 칸](#부록-b-설계서-칸) 순서대로 채운다. `[도구]` 표시 칸은 도구 출력을 그대로 옮기고(손으로 바꾸지 않음), 나머지는 한눈에보기와 원본 장을 보고 적는다. 값마다 근거 게시물 아이디를 달고, 근거가 없으면 "추정"이라고 쓴다.
   - **묘사로 적지 않는다.** 색은 hex, 글씨는 글꼴 이름·굵기·px, 여백은 px, 사진 처리는 "꽉 채움/위 블록/동그라미/누끼" 중 하나.
   - **부품**: 모양표(2단계 2)의 부품 이름·계열을 그대로 쓴다. 부품마다 [부록 A-3](#a-3-슬라이드-부품) 일반 갈래(표지·근거·목록·비교표…) 중 어디에 드는지도 적는다.
   - **글꼴**: [부록 A-4](#a-4-글꼴-추정) 무료 글꼴 목록에서 대체 글꼴을 고르고 원본 추정 이름을 함께 적는다. 손글씨·특이한 글꼴 자리는 눈으로 고르지 말고 겹쳐 잰다:
     ```bash
     python3 -I 도구/부품/글꼴겹침.py <원본 장 jpg> <글자리.json>   # 글 자리마다 후보 글꼴 IoU 1위
     ```
     강원교육모두 Bold/Light를 첫 후보로 하되(두 계정의 원본 글꼴이었음) 다른 후보도 같이 재서 1위를 확인한다.
   - **바탕 비율**: 대표 편 장을 **눈으로** 하나씩 보고 `사진 바탕`(실사 사진이 장의 절반 이상)/`그래픽·단색 바탕`(단색 위 표·카드·글, 작은 누끼 포함)으로 센다. 정보형(건강 정보·영양제 트렌드)과 공구·제품을 따로, 영상·자료 캡처 장은 뺀다. 자동 판정은 쓰지 않는다.
   - **글자 크기·여백**: 종류가 다른 대표 편 3편(1080 원본, 저해상도 제외)에서 제목·본문·작은 글씨의 글자 높이와 상·하·좌·우 여백을 px로 잰다. 원본 장에 글자를 겹쳐 맞춘 **글꼴 크기(px, 1080 기준)**도 적는다 — 디자인 시스템은 이 값을 쓴다(글자 높이를 글꼴 크기로 쓰면 한글 약 10%·숫자 약 25% 작게 그려진다). 원본이 1080이 아니면 1080 기준으로 환산한다.
4. **설계서 쓰기** — 메모를 바탕으로 `$A/04_설계서/설계서.md`를 [부록 B](#부록-b-설계서-칸) 전 칸으로 쓴다. "부품" 칸은 모양표의 부품마다 한 줄(영문 이름·계열·정의·쓰는 종류·편 안 자리·근거 장·견본 장), "종류별 장 구성"은 부품 이름으로 쓴다. 원본이 쓰는 꾸밈이 "쓰지 않는 것"과 부딪히면(예: 그라데이션) 담당자 확인 뒤 계정 예외로 적는다. 빈 칸 없이, 칸마다 근거 게시물 아이디. 실명·가족 이름·사진 파일명·동의 원문은 적지 않는다(그런 메모는 `$A/03_…`·`05_…`에만).
5. **디자인시스템.json 쓰기** — 빈 틀을 복사해 설계서 값으로 채운다.
   ```bash
   cp 도구/디자인시스템_빈틀.json "$A/04_설계서/디자인시스템.json"
   ```
   칸 설명은 [부록 C](#부록-c-디자인시스템json-칸). 값은 설계서와 같아야 한다. `부품` 칸에는 설계서 부품 칸을 그대로 옮긴다(견본 값은 3단계에서 `견본넣기.py`가 넣는다). 아직 못 정한 값은 후보 목록을 `…_선택지`(2개 이상)로 두면 디자인 시스템 화면에 "고르기 전"으로 나오고, 약사님·담당자 확인이 필요한 값은 `_확인전`에 적으면 "확인 전" 질문으로 나온다.
6. **금지목록** — `공통/금지목록.md`가 없으면 [부록 D](#부록-d-금지목록-만드는-법)대로 만든다(사람이 검토). 이 약사님만의 금지어는 설계서 "쓰지 않는 것" 칸에 둔다.
7. **완료 기준·검수** — 만든 대화와 다른 서브에이전트가 아래를 보고 `$A/04_설계서/{날짜}_검수_설계서.md`에 남긴다.
   - [ ] `수집검증.py` 통과(확인 필요 0건, 또는 남은 건마다 이유)
   - [ ] 모양표: 판정 전 장 0 · 설계서·json 부품 = 모양표의 부품(2편 이상) · 부품마다 견본 장이 정해짐 · 무작위 5장의 모양 판정이 그림과 맞음
   - [ ] 설계서 전 칸 채움 · 빈 칸 0 · "추정"은 칸 단위로 10개 이하 · 근거 아이디 없는 값 0
   - [ ] 종류 분류가 판정표로 설명됨("확인 필요"는 이유 있음)
   - [ ] `[도구]` 칸은 도구 출력 그대로
   - [ ] 디자인시스템.json 값과 설계서 값이 같음
   - [ ] 실명·가족 이름·사진 파일명·동의 원문 없음
   - 검수 질문: ① 판정표와 다른 분류가 있는가 ② 값이 묘사("깔끔한")로 적힌 칸이 있는가 ③ 근거 아이디 5개를 무작위로 열어 보면 값이 맞는가 ④ 도구 숫자와 메모 숫자가 다른 곳이 있는가 ⑤ json과 설계서가 다른 칸이 있는가

## 3단계 디자인 시스템

약사님 한 분당 Claude 아티팩트 종류 **"Design System" 1개**. 화면의 컴포넌트는 **설계서의 부품마다 하나씩**이다. 부품마다 원본 견본 장 하나를 픽셀로 재서 견본을 만들고(3-1~3-3), 변환기가 견본·토큰·README를 화면 파일로 묶는다(3-5). 값은 `$A/04_설계서/디자인시스템.json`과 부품 `견본.json`에서만 가져오고, 화면 파일을 손으로 따로 만들지 않는다. 시작 전에 `공통/교훈.md`를 읽는다.

부품 폴더: `$A/05_디자인시스템/부품/<부품 영문 이름>/` — `요소.json`(입력) → `견본.json`·`preview.html`·`render.png`·`cmp.jpg`(왼쪽 원본·오른쪽 렌더)·`README.md`, 깔개·조각 그림.

1. **깔개·조각 그림** — 견본 장의 사진은 그 장 원본에서 얹힌 글만 지운 깔개로 쓴다(견본 전용 — 새 편은 그 편 사진을 넣는다). GPT 키와 "사진을 GPT로 보내기" 동의가 있으면 글 지우기는 [0-4](#0-4-gpt로-그림-만들기고치기)의 고치기로 하고(마스크 = 지울 글 자리, 결과는 그 자리만 원본에 붙여 `bg_보정_AI생성.jpg`), 없거나 결과에 자국이 남으면 아래 도구로 한다.
   ```bash
   .venv-cv/bin/python 도구/부품/사진보정.py <원본 jpg> "$A/05_디자인시스템/부품/<부품>/bg_보정.jpg" --글 x0,y0,x1,y1 --방식 판|질감|메움 [--보호 x0,y0,x1,y1] --확인
   .venv-cv/bin/python 도구/부품/누끼.py <원본 jpg> "$A/05_디자인시스템/부품/<부품>/<이름>.png" --상자 x0,y0,x1,y1
   ```
   - 실명·이름표·남의 아이디는 깔개·조각 그림에서 흐리고, **같은 자리를 `요소.json`의 `원본_가림`에도 적는다**(cmp.jpg 원본 쪽도 가려진다 — 교훈 12).
   - 얼굴·손·제품은 손대지 않는다(`--보호`). 원본 글이 머리·얼굴을 덮고 있던 자리는 그 아래가 원본에도 없으니 메우지 않는다(지어내지 않음) — 같은 자리에 같은 크기 글이 다시 얹힌다.
   - `_확인.jpg`(판 색 기준 명암 8배)를 100%로 열어 자국을 본다. 스티커·공유 아이콘·논문 캡처·고정 머리 묶음(트윗 머리 등)은 지우거나 다시 그리지 말고 원본 조각을 제자리에 쓴다.
2. **견본 만들기** — 견본 장을 재서 `요소.json`(바탕·상자·선·그림·글 요소, 위치·크기·색)을 쓰고 렌더한다.
   ```bash
   python3 -I 도구/부품/글꼴겹침.py <원본 jpg> <글자리.json>          # 글 자리마다 글꼴 고르기
   python3 -I 도구/부품/견본만들기.py <요소.json> <원본 jpg> "$A/05_디자인시스템/부품/<부품>"   # 견본.json·preview.html·render.png·cmp.jpg
   ```
   - 잉크 상자·글 줄 훑기·글꼴 크기 겹쳐 맞추기는 `도구/부품/lib.py` 함수로 잰다(손 어림 금지). 글꼴 크기 = 그 글꼴로 같은 글을 크롬에서 그려 원본 잉크 폭에 맞춘 크기.
   - 색·크기·간격이 설계서 json 값과 같으면 json 값을 쓰고, 원본에서 잰 값이 다르면 `잰_…`으로 따로 적는다.
   - 글꼴에 없는 글자(`·` `><` `=>` 등)는 그 글자만 프리텐다드로(견본만들기가 자동으로 바꾼다).
   - **획 굵기**: 겹침(IoU) 1위라도 `잉크_비`(원본 잉크 / 그린 잉크)가 0.8~1.25 밖이면 굵기가 다른 것이다. 글꼴겹침 표의 "굵기 맞는 1위"를 쓰고, 견본만들기 끝의 `[굵기]` 경고가 0이 되게 한다. 맞는 후보가 없으면(손글씨 등) 원본 잉크 조각을 쓰고 README "원본과 아직 다른 점"에 적는다. `잉크_비`는 단색 바탕(카드·노트) 글에서만 믿는다 — 사진 위 글(벽 모서리·그림자·번짐)이나 줄·테두리가 걸친 글은 원본 잉크가 부풀어 후보가 전부 범위 밖으로 나오니, 그런 자리는 후보를 원본 옆에 나란히 그려 눈으로 고르고 근거를 `근거`에 적는다. 고딕 자리에 손글씨가 1위로 나오면 같은 계열(고딕/손글씨) 안에서 고른다.
   - **기운 글**: 글 줄이 기울어 있으면 글 요소에 `"기울기": 도`(시계 방향)를 적는다. 가로로 펴서 그리지 않는다.
   - `요소.json`에 `json_자리`(`부품.<부품>.견본`), `편_안_자리`, `글_자리`(글 자리마다 한 줄 글자 수·줄 수 범위 — 원본 같은 부품 장 3장 이상에서, 형식 `{"<요소 이름>": "5~14자, 2~7줄"}` — 장만들기가 이 형식으로 한도를 검사한다)를 적는다.
   - `cmp.jpg`를 열어 원본과 나란히 본다. 렌더 아래가 잘리지 않았는지, 글이 얼굴과 20px 이상 떨어졌는지 확인한다. 견본 글을 다른 글로 한 번 바꿔 그려 보고(잉크 조각에 옆 글이 묻어 있지 않은지) 되돌린다.
3. **견본 확인·문서·json** — 부품마다:
   ```bash
   python3 -I 도구/값검사.py "$A/05_디자인시스템/부품/<부품>/preview.html" "$A/05_디자인시스템/부품/<부품>/견본.json" "$A/04_설계서/디자인시스템.json"   # 없는 값 0건
   python3 -I 도구/부품/글자대조.py "$A/05_디자인시스템/부품/<부품>/견본.json" "$A/02_대표슬라이드/슬라이드/<견본 편>/글.md"   # 오타 0건
   python3 -I 도구/부품/부품README.py "$A/05_디자인시스템/부품/<부품>" --모양표 "$A/03_분석/<날짜>_모양표.md"
   ```
   모든 부품이 끝나면 견본 값을 json에 넣는다:
   ```bash
   python3 -I 도구/부품/견본넣기.py "$A/05_디자인시스템/부품" "$A/04_설계서/디자인시스템.json"           # 바뀔 자리 보기
   python3 -I 도구/부품/견본넣기.py "$A/05_디자인시스템/부품" "$A/04_설계서/디자인시스템.json" --write
   ```
   실명·별칭이 견본.json·README·preview·cmp.jpg 원본 쪽까지 0건인지 grep으로 본다. 부품이 많으면 5개씩 worker에 나눠 맡기되, 같은 부품을 2번 넘게 돌려보내지 않는다(3회차는 직접).
4. **부품 검수** — 만든 대화와 다른 서브에이전트가 `$A/05_디자인시스템/{날짜}_검수_부품_N회차.md`에 남긴다.
   - **점수**(부품마다 5점, 모두 4점 이상 통과): ① 모양(원본과 같은 배치) ② 글꼴(겹침 근거) ③ 크기·위치(cmp.jpg) ④ 색(json·잰 값) ⑤ 사진·깔개(자국·얼룩·남의 얼굴 없음) ⑥ README(모양 계열·편 안 자리·글 자리·고정/바꿔 끼우는 자리)
   - **블라인드**: 만든 장 4 + 같은 부품 원본 4를 섞어 판정자 2명(A 흐린 모아보기 / B 낱장, 서로 다른 서브에이전트, 자기 판만)이 실제/만든 것을 고른다. 만든 장 4장 중 3장 이상 '실제'면 통과.
     ```bash
     python3 -I 도구/부품/블라인드.py "$A" "$A/05_디자인시스템/부품" --출력 "$A/05_디자인시스템/블라인드/1판" --회차 3 --재압축
     python3 -I 도구/부품/블라인드.py "$A" "$A/05_디자인시스템/부품" --출력 "$A/05_디자인시스템/블라인드/대조" --대조 <들킨 부품>
     ```
     들킨 부품은 대조 판정(만든 장 자리에 견본 원본) — 원본도 같은 이유로 골라지면 계정 습관이라 고치지 않는다. 판정자가 "깔끔·단순"을 이유로 들면 대조부터 한다.
5. **재료·화면 만들기** — `$A/05_디자인시스템/재료.json`을 만든다(형식은 `도구/디자인시스템변환기.py` 머리말). 부품 견본이 있으면 **장 샘플은 만들지 않는다**(`"장": []`, `"사진": []`) — 같은 모양을 부품 견본이 원본 대조를 거쳐 맡고, 틀 하나로 찍은 장 샘플은 원본과 배치·글 크기가 달라 화면을 흐린다(한 계정 2026-11-12). 아래 "장 샘플 편" 줄은 부품 견본 없이 화면부터 볼 때만 쓴다.
   - 장 샘플 편(부품 견본이 없을 때만): 대표 편 표에서 공구 안내 → 건강 정보 → 영양제 트렌드 → 제품 소개 순, 같은 종류 안에서는 좋아요 순. 슬라이드 글에 금지목록 ①이 있거나 공구·제품 편 캡션이 금지목록 ③을 못 넘으면 건너뛰고, 건너뛴 편과 걸린 장·글을 재료.json에 적는다. 표지 = 1장, 본문 = 2장, 마지막 = 끝 장 글을 `글.md`에서 그대로.
   - 사진: 그 계정 실제 사진에서 글 없는 영역만(얼굴 위 글·이름표는 `프로필사진_가림`·`가림`으로 흐림). 프로필: 표시이름·`@핸들`만, 연락 주소는 가림.
   ```bash
   python3 -I 도구/디자인시스템변환기.py "$A/04_설계서" "$A"   # 부품 폴더가 있으면 부품도 함께 → $A/05_디자인시스템/project/
   ```
   ① `올릴사진/`(프로필·`part-*` 부품 그림)을 Design System 아티팩트 assets로 올린다(약사님 얼굴이 든 그림은 담당자 승인 뒤) → ② `사진아이디.json`에 `/_blob/<id>` → ③ 변환기 다시 → ④ `project/` 파일을 아티팩트에 올린다(다시 올릴 때는 **같은 주소**). 변환기 보고의 "설계서에 값 없음"·"글꼴 못 부름"·"사진 올리기 전"이 나오면 채운다.
6. **구성 샘플** — 모양표의 종류별 구성안 순서로 부품 렌더를 이어 붙여 담당자에게 보낸다(장마다 견본 글이라 내용은 안 이어짐 — 구성·모양 확인용).
   ```bash
   python3 -I 도구/구성샘플.py "$A/05_디자인시스템/부품" <부품1> <부품2> … --출력 "$A/05_디자인시스템/구성샘플_<종류>.jpg"
   ```
7. **공유·고치기** — 아티팩트는 처음엔 만든 사람만 본다. 담당자가 편집 권한자에게 공유하고, 약사님께 보낼지 정한다(약사님 의견은 담당자가 댓글로 대신 적는다). 화면에서 고친 토큰·댓글은 담당자(의 Claude)가 읽어: ① 디자인시스템.json(부품 값이면 그 부품 `요소.json` → 견본만들기 → 견본넣기) ② 설계서.md 같은 칸(근거 `○○ 확인(날짜)`) ③ 변환기 ④ 같은 주소에 다시 올림. 옮긴 고침은 '반영됨(날짜)', 안 옮긴 고침은 '보류(이유)'. 같은 칸에 고침이 둘 이상이거나 얼굴 AI·금지목록·광고 기준에 걸리면 옮기지 않고 묻는다. 모든 계정에 해당할 고침은 `공통/교훈.md` 제안 절에 적는다.
8. **기록·완료 기준** — `$A/05_디자인시스템/{날짜}_검토_디자인시스템화면.md`에 화면 주소·만든 날·부품 목록·반영한 고침·확인한 사람과 날짜·약사님 의견 여부를 적는다. 다른 서브에이전트가 아래를 보고 `{날짜}_검수_디자인시스템화면.md`에 남긴다.
   - [ ] 화면의 부품 컴포넌트 = 설계서 부품 목록(빠진 것 0) · 부품마다 README `## 모양 계열` 줄 있음
   - [ ] 부품 검수(3-4) 점수·블라인드 통과 기록 있음
   - [ ] tokens.json과 부품 preview의 hex·px·글꼴 이름이 모두 디자인시스템.json(부품 견본 포함) 안에 있다(`값검사.py` 0건, 화면 틀 제외)
   - [ ] 원본 추정 글꼴이 아니라 대체 글꼴로 그렸고 "대체 글꼴" 표시가 있다 · "글꼴 못 부름" 0건(고르기 전 후보 제외)
   - [ ] 고르기 전 후보마다 "고르기 전" 표시 · 확인 전 칸이 질문으로 나온다
   - [ ] 프로필·부품 그림에 실명·가족 이름·연락처·외부 링크·하이라이트 이름이 없다 · 사진은 그 계정 실제 사진이고 출처가 있다
   - [ ] 고친 토큰이 다시 열어도 남고, json을 고쳐 같은 주소에 다시 올리면 화면이 바뀐다 · 손대지 않은 고침 0
   - 검수 질문: ① 토큰·부품에 json과 다른 값 ② 빠진 부품·고르기·확인 칸 ③ 개인정보 ④ 부품 장이 "AI 카드뉴스" 모양인가(그 계정 실제 게시물과 나란히)
   여기까지 끝나면 담당자 확인을 기다리지 않고 화면 주소·검수 결과·확인 전 칸을 보고한다(`읽어주세요.md`에 "담당자 확인 대기"). 담당자 확인이 기록되면 3단계가 끝난다. 확인을 받으면 설계서 "검토 기록" 칸에 "담당자 확인({이름}, {날짜}) — 약사님 의견 받으면 덧붙임"을 적는다.

## 4단계 캐러셀 생성 — 기획서를 받으면

3단계가 끝난 약사님에게만 쓴다. 편 폴더: `$A/06_캐러셀/{YYYY-MM-DD}_{편이름}/` (`brief.md`·`구성.md`·`구성.json`·`장별글.md`·`아티팩트.md`·`검수_N회차.md`·`log.md`)

1. **기획서 읽기** — 기획서에서 장별 글(`피드1.` `피드2.`…)·`*` 디자인 요청·캡션 완성본·레퍼런스 편을 뽑아 `brief.md`에 옮긴다. 노션 링크면 Aside로 열어 `snapshot(page)`으로 본문을 읽는다(읽기만, 고치지 않는다 — 노션 커넥터는 그 페이지 권한이 없을 수 있다. 본문이 길면 스크롤하며 블록을 모은다).
   - **기획서가 이 계정 것인지 먼저 본다**(계정 이름·실행 계획·캡션 양식 줄). 다른 계정용이면 만들지 않고 담당자에게 묻는다.
   - **`피드N.` 장별 글이 없는 기획서(릴스 대본 등)**: 담당자에게 묻고, 하기로 하면 대본·캡션에 있는 문장만으로 장별 글 초안을 뽑는다(새 주장·숫자·순위 말을 더하지 않는다). 근거 자료 링크(논문 등)는 주소까지 brief에 옮기고, 논문이 아닌 링크(대화 기록 등)는 "출처 없음"으로 적어 알린다.
   - 캡션은 **그대로** 쓴다(새로 쓰지 않는다). 캡션에 광고 기준 위반이 있어도 고치지 않고, 걸린 줄과 이유를 알리고 그 편은 멈춘다.
   - 레퍼런스 편은 구성만 참고하고 그 사진·그림은 쓰지 않는다.
2. **사진 재료 확인(장 구성 전에)** — 사진 바탕 부품을 몇 장 쓸지 어림한 뒤 글자 없는 본인 사진이 그만큼 있는지 센다.
   ```bash
   python3 -I 도구/사진재료.py "$A" --필요 <사진 장 수>   # 끝 코드 1 = 재료 부족
   ```
   모자라면 만들기 전에 담당자에게 알리고 고르게 한다: ① 그 편의 사진을 약사님께 받는다(담당자가 정한다 — 4의 "따로 요청하지 않는다"의 예외) ② 사진 장을 줄이고 그래픽 부품으로(GPT 키가 있으면 그래픽 장의 소품·아이콘 그림을 0-4로 새로 만들 수 있다 — 사진 장을 생성 사진으로 대신하지는 않는다) ③ 기존 게시물 사진에서 얹힌 글만 지워 다시 쓴다 ④ 멈춘다. ③은 블라인드를 통과하기 어렵다(한 계정 2026-11-12: 3회 모두 4장 다 들킴 — 옛 상자가 글보다 크고 새 글만 또렷하다). ③을 고르면 그 한계를 담당자에게 먼저 말한다.
3. **종류 판정 + 장 구성** — 판정표로 종류를 정하고 설계서 "종류별 장 구성"(부품 이름)과 모양표의 종류별 구성안을 따른다. 장마다 **부품 하나**를 고른다(디자인 시스템에 없는 모양은 만들지 않는다 — 원본 2편 이상에 있으면 3단계로 돌아가 부품을 더하고, 1편뿐이면 다른 부품으로 나눈다). 장 수는 기획서 `피드N.` 수를 우선하되 평소 범위를 넘으면 합친다. 부품 README의 `## 편 안 자리`를 지킨다(2장째 전용 부품을 표지로 쓰지 않는다). 후기·댓글 캡처 부품은 기획서에 새 캡처가 있을 때만 고른다("언제나 지키는 것").
   - **한 편 안 비슷한 장 금지**: 부품 README의 `## 모양 계열`로 묶어 계열마다 1장만 — README에 "최대 N장"이 적힌 계열(원본이 한 편에 여러 장 쓰는 계열, 예: 실사+자막)은 N장까지. 내용이 남으면 다른 계열 부품으로 나누거나 캡션으로 보낸다.
   - **사진 바탕 비율**은 설계서 `바탕 비율`을 따른다.
   - **편 사이 중복 금지**: 최근 3편과 ① 표지 부품이 같지 않고 ② 장 모양 계열 순서가 똑같지 않고 ③ 같은 사진을 쓰지 않는다.
   - 장 순서의 근거 편을 `구성.md`에, 쓴 부품을 `구성.json`(`{"편", "날짜", "부품": [장 순서대로 부품 영문 이름], "사진": [쓴 사진 출처]}`)에 남기고 검사한다.
   ```bash
   python3 -I 도구/비슷한장검사.py "$A/05_디자인시스템/부품" "$A/06_캐러셀/{새 편}/구성.json" "$A/06_캐러셀/{최근 편}/구성.json" … --약사님폴더 "$A"
   ```
   끝 코드 1(걸림)이면 장 구성을 다시 짠다. `--약사님폴더`를 주면 사진을 이름이 아니라 **그림으로** 견준다(같은 컷을 다른 게시물에 다시 쓰는 계정이 있다 — 사진을 고른 뒤 한 번 더 돌린다).
4. **장별 글 → 글 확인** — 부품 README `## 글 자리`의 한도(한 줄 글자 수·줄 수) 안에서 장별 글을 `장별글.md`에 적고(README에 없으면 원본 같은 부품 장 3장 이상에서 재서 README에 더한다), 장에는 핵심 1~2줄만 둔다(설명은 캡션으로, 새 주장 금지). 금지목록 + 설계서 "쓰지 않는 것"으로 먼저 거른다(기존 게시물에 그런 문장이 있어도 따라 쓰지 않는다). 장별 글 표를 **디자인 전에** 약사님께 보인다(전달은 담당자). 기획서 글을 줄이거나 나눈 곳만 표시한다.
5. **재료 모으기** — 사진은 ① 기획서가 가리킨 것 ② 그 약사님 인스타의 본인·제품 사진 ③ 제품 공식 사이트 실사(출처 기록) 순. 약사님께 원본 사진을 따로 요청하지 않는다.
   - 글자 없는 사진이 필요하면 ① 잘라 쓰기(보정 없음) → ② 글자·스티커만 지우는 보정(얼굴·제품 불변, 원본 보존) → ③ 그래도 안 되는 장만 AI 배경(`_AI생성`, 배경·장식만). ②·③은 GPT 키가 있으면 [0-4](#0-4-gpt로-그림-만들기고치기)로 한다(②는 "사진을 GPT로 보내기" 동의도 있어야 한다 — 결과는 `_AI생성`). 키·동의가 없거나 GPT 결과에 자국이 남으면 ②는 아래 `사진준비.py`(`_보정`)로 한다. 누끼는 `도구/부품/누끼.py`.
   - 키 없을 때 ②는 편 폴더 `재료/일.json`에 사진마다 지울 자리를 적고 돌린다(상자 안 글은 상자 색으로 메움, 사진 위 글은 `사진보정.py`, 남은 얼룩은 옆 면을 옮겨 붙임).
     ```bash
     .venv-cv/bin/python 도구/부품/사진준비.py "$A/06_캐러셀/{편}/재료/일.json" --출력 "$A/06_캐러셀/{편}/재료"
     ```
     글이 머리카락·얼굴 위에 있는 사진은 지우지 못하니 쓰지 않는다. 지운 자리는 크게 열어 보고, 얼룩이 남으면 그 자리를 글 상자로 완전히 덮거나 옮겨 붙인다. 부품 견본의 깔개(`bg_보정.jpg`)는 견본 전용이다 — 재료가 없어 쓰게 되면 `구성.md`에 적는다.
   - **옷·배경 변형**(같은 사진을 다른 편에 다시 쓸 때만) — 쓸 수 있는 사진이 최근 3편에 쓴 것이거나 같은 컷(`비슷한장검사.py`에 걸림)뿐일 때, 옷이나 배경을 GPT로 바꿔 쓴다. 조건: GPT 키 + 동의기록의 "얼굴 외(복장·배경) AI 수정 = 예" + "사진을 GPT로 보내기 = 예". 하나라도 없으면 하지 않는다(사진 장을 줄이거나 사진을 받는다).
     ```bash
     python3 도구/부품/gpt그림.py 고치기 <글 지운 사진> "$A/06_캐러셀/{편}/재료/<이름>_AI생성.jpg" --자리 <옷 또는 배경 상자> --보호 <얼굴·머리카락> --보호 <손·제품> --프롬프트 "<바꿀 것>" --기록 "$A/06_캐러셀/{편}/log.md"
     ```
     - 바꾸는 것은 **옷(색·종류)과 배경(장소·벽·소품)뿐**이다. 얼굴·머리 모양·손·체형·포즈·제품은 `--보호`로 묶어 원본 그대로 둔다. 포즈는 바꾸지 않는다.
     - 옷은 그 계정 `사진메모.json`의 복장 기록에 있는 것(가운·평소 옷 색) 안에서 고른다 — 그 약사님이 입지 않는 옷·로고·글자가 든 옷은 만들지 않는다. 배경도 그 계정에 나온 장소(약국·집·카페 등) 안에서.
     - 한 장에 옷과 배경을 같이 바꾸지 않는다(둘 다 바꾸면 얼굴만 남아 합성으로 보인다). 한 편에 변형 사진은 2장까지.
     - 결과를 100%로 열어 목·손목·머리카락 경계의 이음선, 조명 방향, 그림자를 본다. 어긋나면 프롬프트를 고쳐 2번까지 다시, 그래도 남으면 그 사진은 쓰지 않는다.
     - `구성.md`와 아티팩트 메모에 "옷/배경을 GPT로 바꾼 장"을 적고, 4-9에서 약사님께 그 장을 따로 짚어 보인다 — **약사님이 그 장을 확인하기 전에는 게시용으로 확정하지 않는다.**
   - 제품 사진은 ① 그 약사님 게시물 실사(누끼) → ② 공식 사이트 실사 → ③ 못 구할 때만 AI 일반 영양제 그림(0-4, 상표·글자 없음, `_AI생성`). 성분표·검사지·근거 자료는 실사·원본만.
   - 아이콘·소품은 이모지·단순 도형 대신 ① 이전 게시물에서 누끼 ② 없으면 AI로 그린다(0-4, 상표·글자·얼굴 없음, 그 계정 그림 꼴, `_AI생성`). GPT 키가 없으면 그 장은 그림 없이 구성한다.
6. **디자인** — 장마다 그 부품의 `preview.html`을 틀로 쓰고 **글과 사진만 바꾼다**(색·크기·위치는 디자인시스템.json·부품 견본 값만, 새 색·새 꾸밈 금지).
   ```bash
   python3 -I 도구/장만들기.py "$A" "$A/06_캐러셀/{편}" --장 <장.json>   # 장마다 slide.html → render.png
   python3 -I 도구/값검사.py "$A/06_캐러셀/{편}/s/<n>_<부품>/slide.html" "$A/04_설계서/디자인시스템.json"   # 없는 값 0건
   python3 -I 도구/부품/글자대조.py "$A/06_캐러셀/{편}/s/<n>_<부품>/slide.html" "$A/06_캐러셀/{편}/장별글.md"
   ```
   - **사진마다 글 상자 자리가 다른 부품**(설계서 `사진위글자.방식`이 "장마다 자유 배치"인 계정의 실사+자막 등): 장.json에 `"요소"`(상자·글·`글줄`)를 적어 그 사진의 상자 자리에 글을 앉힌다(`도구/장만들기.py` 머리말). 글꼴 크기·색은 디자인시스템.json 값만 쓰고, 자리 좌표는 json 밖 값이니 `값검사.py`에 장.json을 함께 준다. 상자는 글 크기에 맞춘다(옛 상자가 더 크면 덮개처럼 보인다). 출처 줄(숫자 장)은 따로 붙인 라벨이 아니라 그 글 상자 안 작은 줄(24px)로 넣는다. 한 편의 장들이 같은 상자·글꼴 하나로 판박이가 되지 않게, 그 계정 원본이 섞어 쓰는 상자 모양·굵기를 따라 섞는다.
   새 글은 견본의 낱말 조각 자리가 아니라 **줄 단위로** 다시 앉힌다(줄이 쏠리거나 겹치지 않게). 글이 얼굴과 20px 이상 떨어지게 한다 — 장만들기가 사진 장마다 얼굴을 찾아(macOS Vision, 위치만) 글이 머리 상자+20px 안이면 `[얼굴]` 경고와 `얼굴확인.jpg`(빨강 = 겹침)를 남기니, 경고가 0이 될 때까지 사진 자르기·글 자리를 옮긴다(교훈 10). 못 찾는 얼굴(가린·뒷모습)이 있으니 render.png도 눈으로 본다. `*` 요청은 꼭 반영하고, 못 하면 이유를 보고에 적는다.
7. **아티팩트** — 한 편 = 아티팩트 하나(`python3 -I 도구/캐러셀아티팩트.py "$A/06_캐러셀/{편}"` → `아티팩트/캐러셀.html` + 장 그림, 그대로 올린다 — 다시 올릴 때는 같은 주소, 없어진 장 그림은 지운다). 장을 순서대로 1080×1350 프레임(json `출력_크기_기본`이 다르면 그 크기, px는 1080 좌표계 기준이라 1440이면 ×1.333 배율)으로 두고 맨 아래에 캡션을 붙인다. PNG·캔바 파일은 만들지 않는다. 주소를 `아티팩트.md`에 날짜·안 이름과 함께 적는다. 시안이 여럿이면 안마다 아티팩트 하나.
8. **검수(최대 3번)** — 기계 점검 → **만든 대화와 다른 서브에이전트**에게 아티팩트·brief·설계서·디자인시스템.json·금지목록만 주고 판정하게 한다(같은 대화에서 검수하면 거의 다 통과로 나온다). 걸리면 6으로 돌아간다. 기록은 `검수_N회차.md`(점수표에 직전 판 열).
   - 기계 점검: 장 수가 평소 범위 안 · 프레임 크기 · brief에 없는 숫자·성분명 없음 · 금지목록·"쓰지 않는 것" 없음(슬라이드 글) · 같은 사진 두 번 없음·최근 3편과 안 겹침 · 색이 json 값 안 · 워터마크가 종류에 맞음 · AI가 얼굴에 손대지 않음·`_AI생성` 표시 · 공구·제품 편 캡션에 광고/협찬/공구 표시가 금지목록 ③대로
   - 블라인드 먼저: 원본 장 4장(같은 부품)과 만든 장 4장을 섞어 주제 글을 가리고, 정답을 보기 전에 판단한다. 판은 `python3 -I 도구/편블라인드.py "$A" "$A/06_캐러셀/{편}" --출력 "$A/06_캐러셀/{편}/블라인드_N회차" --제외 <이전 회차 폴더>`로 만들고(만든 장도 같은 크기·품질로 재압축, 그 편이 쓴 사진의 원본 장은 뺀다), 판정자에게는 그 폴더의 `판정_지시문.md`만 준다. 들킨 장은 대조 판정.
   - 글자 대조: `글자대조.py`로 장 글과 `장별글.md`를 맞춰 본다(오타는 값 검사·점수·블라인드 어디서도 안 잡힌다).
   - 점수(5점): 1 피드 일치(같은 종류 원본 2편 한눈에보기와 나란히) · 2 가독성(폰 폭 390px에서 본문이 읽힘 — 1080 기준 약 30px 이상, 출처 줄 24px 예외) · 3 리듬(장 순서가 원본 흐름과 맞음) · 4 내용(기획서와 같은 뜻, 새 주장·빠진 핵심 없음) · 5 사진·꾸밈(주제와 맞고 라벨 효능 문구·덮은 자국 없음) · 6 규칙(부품 고정 자리, 금지목록 ① 없음, 출처 줄) · 7 블라인드(스타일만으로 티 나는 만든 장 4장 중 1장 이하) · 8 직전 판 대비 나빠진 항목 없음 · 9 비슷한 장 없음
   - **통과** = 1~6·8 모두 4점 이상 + 7·9 통과
9. **사람 확인** — 담당자가 아티팩트를 먼저 보고, 그다음 약사님께 아티팩트 주소와 캡션을 보낸다. 고칠 점은 `brief.md`에 적고 6부터 다시. 검수 3번에 통과하지 못하면 더 돌리지 않고 남은 점과 함께 담당자에게 넘긴다(게시용으로 확정하지 않는다).
10. **마무리** — 최종 아티팩트 주소·캡션을 편 폴더에 두고 `$A/읽어주세요.md`를 갱신한다. 비용(AI 이미지 등)은 `log.md`에, 배운 점은 `$A/04_설계서/배운점.md`에 날짜와 함께 덧붙인다.

## 언제나 지키는 것

- 노션·인스타는 Aside 브라우저로 읽기만 한다. 로그인·비밀번호는 사람이 다룬다. 결제·약관 동의·영구 삭제는 하지 않는다.
- **약사님 얼굴은 AI로 만들거나 고치지 않는다**(동의 문구가 넓어도 마찬가지). 얼굴 외(복장·배경)는 동의가 있을 때만(4단계 5 "옷·배경 변형" — 포즈·체형은 바꾸지 않는다), 결과는 약사님 검수 뒤에만 게시. AI가 손댄 파일은 이름에 `_AI생성`, AI 표시(C2PA)는 지우지 않는다.
- GPT 키(맥 키체인 / 윈도우 `.env`)는 대화창으로 받지 않고, 화면·기록·보고·아티팩트 어디에도 적지 않고, 작업 폴더 밖으로 복사하지 않는다. 약사님 사진은 "사진을 GPT로 보내기" 동의가 있을 때만 보낸다(0-4).
- 기존 게시물의 후기·댓글·DM 캡처는 새 편에 재사용하지 않는다(디자인 참고와 부품 견본 전용). 후기·댓글 캡처 부품(계열 ㉫, 예: `ReviewCapture`)은 **기획서가 새 캡처를 줄 때만** 고르고, 없으면 다른 부품으로 구성한다. 새 캡처도 효능 후기면 금지목록 ①에 걸리니 쓰지 않는다(맛·사용감·배송 후기만). 본인 계정 프로필 캡처(`CtaProfileCapture`)는 이 규칙 대상이 아니다 — 그때의 화면을 다시 받아 실명·연락처를 가리고 쓴다.
- `04_설계서/`(설계서.md·디자인시스템.json)와 `05_디자인시스템/` 화면에는 실명·가족 이름·사진 파일명·동의 원문을 적지 않는다. 그런 것은 `03_분석/`·`동의기록.md`에만.
- 캡션 수신 폴더(`01_수집/캡션수신/`)는 캡션 원문이 들어 있으니 공유하지 않는다.
- 작업 폴더를 남에게 넘길 때는 약사님 폴더(사진·캡션·동의기록)와 `.env`·`.venv-cv`를 빼고 넘긴다.
- 이 폴더가 git 저장소면 `.env`·`.venv-cv`는 올리지 않는다(`.gitignore`). 저장소는 비공개로 두고, 올리기(push)는 사람이 말했을 때만 한다.
- 30일이 지났거나 피드 분위기가 바뀌면 1~3단계를 다시 하고, 디자인 시스템은 같은 주소에 다시 올린다.
- 3·4단계에서 새로 들킨 것·고친 것 중 다른 계정에도 해당할 것은 `공통/교훈.md` "제안" 절에 한 줄로 적는다(형식: `- [계정, 날짜] 무엇 / 왜 공통인지 / 근거 장`).

## 부록 A. 판단 규칙 (누가 해도 같은 값이 나오게)

### A-1. 종류 판정표
캡션·슬라이드에서 단서를 찾아 순서대로 본다. 먼저 맞는 것이 종류다.

| 순서 | 단서(캡션·표지) | 종류 |
|---|---|---|
| 1 | 가족·일상·여행·감사 인사가 주제, 제품 설명 없음 | 개인 일상(디자인 기준 제외) |
| 2 | "공구 오픈/마감/곧 마감/팝업/DM 주세요/링크", 가격·할인·기간 표시 | 공구 안내 |
| 3 | "사전알림/나눔/출시/입고/이런 분께", 특정 제품 1~2종 설명, 아직 판매 중 아님 | 제품 소개 |
| 4 | "요즘/트렌드/인기/비교/vs/순위", 제품 여러 종 비교·성분 비교 | 영양제 트렌드 |
| 5 | 증상·질환·생활 습관 설명, 제품명 없거나 보조 | 건강 정보 |
| 6 | 둘 이상에 걸침 | 표지 제목이 가리키는 쪽. 그래도 애매하면 "확인 필요"(이유 적기) |

한 종류 안에서 디자인이 갈리면(예: 공구 "오픈형"과 "곧 마감·팝업") 하위 유형으로 나눠 적는다.

### A-2. 대표 편 고르기
- **릴스를 뺀 최근 캐러셀·사진 60개** 안에서 종류별로 좋아요 상위 편: 공구 안내 6 · 건강 정보 5 · 영양제 트렌드 4 · 제품 소개 4(없는 종류는 비움). 좋아요가 숨겨진 계정은 최신순.
- 60개 안에서 정원을 못 채우면 더 예전 캐러셀로 거슬러 올라가 그 종류만 채우고 "60개 밖(보충)"으로 표시한다.
- 1장짜리·릴스는 뺀다. 같은 주제 편이 둘이면 최신 것.
- 수집 불가 편(삭제·비공개, 전부 동영상, 그림이 안 보임)은 같은 종류 다음 순위로 바꾸고 `대체(사유, 원래 편 아이디)`를 적는다.

### A-3. 슬라이드 부품(일반 갈래)

계정마다 실제 부품(컴포넌트)은 모양 판정(A-5)으로 정하고, 이 표는 그 부품이 편 안에서 하는 역할을 적는 갈래다.

| 부품 | 정의 | 아닌 것 |
|---|---|---|
| 표지 | 편의 첫 장. 제목이 가장 큰 글자 | 제목+본문이 한 장에 있으면 "제목장 겸용" |
| 공감 | 독자의 상황·고민을 말하는 장(질문·증상 나열) | 근거 숫자가 주면 근거·목록 |
| 근거·목록 | 성분·효과·이유를 항목으로 나열한 장 | 두 가지 이상을 나란히 놓으면 비교표 |
| 비교표 | 행·열이 있는 표, 또는 A vs B 나란히 | 체크 목록 하나는 근거·목록 |
| 사진+메모 | 사진이 절반 이상이고 글은 한두 줄 | 글이 절반 넘으면 근거·목록 |
| 주의 | "주의/피하세요/이런 분은" 경고가 주제 | |
| 가격 | 가격·할인·구성·기간이 주제 | 가격이 한 줄만 있으면 그 장의 원래 부품 |
| CTA | 마지막 장. 저장·DM·프로필·링크 유도 | 마지막 장이어도 내용 장이면 그 부품 |

### A-5. 모양 판정(부품 이름)
- **모양** = 장을 멀리서 봤을 때 보이는 배치: 바탕(사진 꽉 채움 / 덮은 사진 / 단색 / 종이·노트 / 캡처) + 글이 놓이는 방식(바 자막 / 둥근 라벨 / 큰 제목 / 표 / 카드 / 번호 목록 / 누끼 행 …) + 주된 그림(본인 사진 / 제품 누끼 / 원형 얼굴 …). 글 내용·주제는 보지 않는다.
- **부품 이름**: 영문 CamelCase. 다른 계정에서 같은 모양에 쓴 이름이 있으면 그대로 쓴다(예: `CoverPhotoTitle` 사진 표지+큰 제목 · `PhotoCaption` 실사+자막 바 · `DimPhotoInfo` 덮은 사진 위 정보 글 · `PlainTypeSlide` 단색 바탕 글 장 · `GridTable` 격자 표 · `NukkiRowList` 누끼 행 목록 · `TopFigureList` 순위·수치 목록 · `CardGrid` 카드 격자 · `NumberedNotes` 번호 메모 · `PaperCards` 논문 카드 · `TweetCardList` 트윗 카드 목록 · `ProductPanel` 제품 판 · `OptionPriceCard` 옵션·가격 카드 · `ReviewCapture` 후기 캡처 · `CtaPhotoCard` 마지막 장 사진 카드 · `CtaProfileCapture` 프로필 캡처 마지막 장 · `CtaCirclePhoto` 원형 사진 마지막 장). 없으면 새 이름을 짓고 모양 한 줄을 남긴다.
- **계열**: ㉠ 사진 표지 · ㉡ 실사+자막 · ㉢ 덮은 사진 정보 · ㉣ 단색 글 장 · ㉤ 표 · ㉥ 순위·수치 · ㉦ 누끼 행 · ㉧ 마지막 장 · ㉨ 카드 · ㉩ 번호 목록 · ㉪ 가격·옵션 · ㉫ 후기·자료 캡처 — 없으면 이어서 붙인다. 계열은 "비슷한 장 금지"의 단위다.
- 같은 모양인데 색·글 수만 다르면 같은 부품, 배치가 다르면(예: 표 머리 유무, 사진 위치가 위↔꽉) 다른 부품. 애매하면 "확인 필요"로 두고 모양표에서 사람이 정한다.

### A-4. 글꼴 추정
- 대체 글꼴 후보는 **무료 글꼴 목록**에서만: 프리텐다드, 노토 산스 KR, 나눔스퀘어(라운드·네오), 나눔고딕, 나눔명조, 본고딕, 지마켓 산스, 에스코어 드림, 카페24 서라운드·아네모네·당당해, 검은고딕(Black Han Sans), 주아, 도현, 여기어때 잘난체, 배민 한나·주아·도현·연성, 강원교육모두, 학교안심, 마포 글꼴, 싱글데이(손글씨, 2026-11-11 추가 — `도구/글꼴/`에 OFL 파일 있어 화면에서 불림). 목록 밖 글꼴은 "원본 추정 이름"에만 적는다.

- 디자인 시스템 화면에서 실제로 불리는 글꼴은 `도구/글꼴/`에 파일이 있는 것뿐이다(`도구/README.md`). 새 대체 글꼴을 쓰려면 OFL 등 무료 라이선스 파일과 함께 `도구/글꼴/`에 넣고 변환기 `글꼴표`·`글꼴파일`에 등록한다.

## 부록 C. 디자인시스템.json 칸

`도구/디자인시스템_빈틀.json`을 복사해 채운다. 칸 이름은 바꾸지 않는다(변환기가 이 이름으로 읽는다). 값이 없는 칸은 비워 두면 화면에 "설계서에 값 없음"으로 나온다. px는 모두 1080×1350 좌표계 기준.

| 칸 | 값 |
|---|---|
| `_계정` | `{표시이름}_{계정}` |
| `_작성일` · `_확인전` | 작성일 / 확인이 필요한 칸 `{"칸": "질문"}` |
| `출력_크기_기본` | `[가로, 세로]` (기본 `[1080, 1350]`) |
| `표지_패턴` | 표지 패턴 문장 목록 |
| `색.바탕` | hex 목록(첫 번째가 기본 바탕) |
| `색.본문`·`색.제목`·`색.본문_사진위` | hex |
| `색.강조`·`색.형광펜` | `{"역할": 설명, "선택지": hex}` — 못 정했으면 `"선택지": [후보 hex…]` |

## 부록 D. 금지목록 만드는 법

`공통/금지목록.md`가 없을 때 Claude가 초안을 쓰고 사람이 검토한다. 계속 늘려 간다.

- **① 광고 심의**: 식약처 식품 등의 표시·광고 기준을 바탕으로 — 본인 체험담(효능 후기), 인정받지 않은 기능성·질병 예방·치료 표현, 효능 단정. **"약사가 추천" + 효능 단정이 한 문장·한 장에 붙으면 금지**("약사가 만든/개발한/배합한"처럼 사실만 적는 표현은 허용). "약사 픽" 같은 표현을 쓸지는 설계서 "쓰지 않는 것"에서 정한다.
- **② AI 티 어휘·구문**: "~하는 것이 중요합니다", "함께 알아볼까요", 기계적인 3개 나열, 문장마다 이모지, "~의 모든 것/총정리" 등. 그 약사님 설계서 "자주 쓰는 표현"에 있는 말은 예외.
- **③ 광고·협찬·공구 표시**: 공구 안내·제품 소개 편 캡션에 광고/협찬/공구 표시가 있어야 하는 위치 규칙.
- 쓰는 곳: 슬라이드 안 글. 캡션은 기획서 그대로 쓰므로 고치지 않고, 걸리면 알리고 멈춘다.

## 부록 E. 기획서 주는 법
3단계가 끝났을 때(실행 규칙 6) 아래를 그대로 보여 준다.

> **기획서를 주시면 캐러셀을 만듭니다.** 디자인 시스템 화면을 먼저 확인("확인했어")해 주세요.
>
> **주는 방법** — 셋 중 하나: 노션 링크 · 대화창에 붙여 넣은 글 · 파일 경로
>
> **들어 있으면 좋은 것**
> 1. **장별 글** — 장마다 `피드1.` `피드2.` … 로 나눠 적습니다. 한 장에는 핵심 1~2줄만(긴 설명은 캡션으로).
> 2. **캡션 완성본** — 고치지 않고 그대로 씁니다.
> 3. **근거** — 수치·효능을 말하면 논문 주소 등 출처를 같이 적습니다. 기획서에 없는 사실·수치는 넣지 않습니다.
> 4. **디자인 요청**(선택) — 줄 앞에 `*`를 붙여 적습니다(예: `* 표지는 제품 사진으로`).
> 5. **그 편에 쓸 사진**(선택) — 글자가 얹히지 않은 본인·제품 사진이 있으면 폴더 경로를 알려 주세요. 글이 얹힌 기존 사진을 지워 쓰거나 AI로 만든 사진은 만든 티가 납니다.
>
> **예**
> ```text
> 피드1. 아침 공복에 먹으면 안 되는 영양제 3가지
> 피드2. 철분 — 속이 쓰리면 식후로
> 피드3. …
> * 표지는 본인 사진
> 캡션: (완성본)
> 근거: https://pubmed.ncbi.nlm.nih.gov/…
> ```
>
> 장별 글이 없는 글(릴스 대본 등)을 주시면 그 안의 문장만으로 장별 글 초안을 뽑아 먼저 보여 드립니다.
